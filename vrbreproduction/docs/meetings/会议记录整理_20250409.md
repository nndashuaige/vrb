## 一、Heatmap 问题与调整

### 1.1 高斯核参数问题
- 当前 heatmap 分布有问题：5 个 contact point 中，**高斯热区只包住了其中 3–4 个，有 2 个没被包到**
- 原因：这两个点权重给得特别低
- **解决方法**：把高斯核调得更平滑一点（增大 sigma），让热区能覆盖到所有点
- 学生代码里加了一个 `amplitude`（语音识别为 "attitude" / "波幅"）参数，老师建议调小试试，让分布更正常

### 1.2 Heatmap + Trajectory 叠加可视化

- 老师提醒：**trajectory 不是随便画条线，要从物体表面（contact point 位置）出发画出来**

## 三、Inpainting 方法（关键任务）

### 3.1 为什么要用 Inpainting？

VRB 论文里有一个重要要求：

> **训练数据里不能有人的手**

原因：VRB 要从人类视频学习 affordance，但模型输出的表示必须是"人类无关"的（human-agnostic）。如果训练图里还有手，模型可能会学到"手在图里"这个偏置，而不是纯物体的 affordance。

### 3.2 原论文的做法（推测）

如果某一帧有手，**直接把那帧扔掉不用**。

### 3.3 这样做的问题

- 人类视频里手出现的频率很高，**如果全部丢弃，会丢掉大量数据**
- 学生担心：不知道论文里的"保留率"是多少，担心自己丢多了或丢少了，训练数据量和别人不一样

### 3.4 带教的建议：不丢弃，而是把手"修掉"

具体流程：
1. **检测手部区域**：
   - 方法 A：用皮肤颜色检测（简单快速）
   - 方法 B：用现有的手部检测算法（如果检测不到再用颜色）
2. **打 Mask**：在检测到的手部区域打 mask（纯白或纯黑都可以）
3. **Inpainting 补全**：用 inpainting 算法把 mask 区域（即手部）补上，用周围的背景像素填充
4. **保留这帧**：补完之后这帧就可以作为"没有手"的训练数据用了

### 3.5 对 Inpainting 的要求

- **速度要快**：不能太慢，因为数据量可能很大
- **效果要自然**：补上的区域要和周围背景融合
- 带教提到 Navier-Stokes Inpainting 作为一种参考，但说"现在这种工作很多很多"，可以找更好的、更快的方法

### 3.6 总结

| 问题 | 原论文做法 | 带教建议 |
|---|---|---|
| 训练图里有手 | 直接丢弃该帧 | **不丢弃**，先检测手部 → 打 mask → inpainting 补全 → 保留 |
| 优点 | 简单 | **保留更多训练数据**，不浪费 |
| 风险 | 数据量减少 | inpainting 速度不能太慢；补全效果要自然 |

## 四、网络结构理解（High Priority）

带教要求学生下次会议解释 VRB 的网络结构：

### 4.1 需要讲清楚的内容
- 每个模块的**输入输出是什么**
- 每个模块的**维度是什么**
- 每个模块**在干什么**

### 4.2 重点看这些文件
- `networks/model.py`
- `networks/layer.py`
- `networks/traj.py`

### 4.3 需要理解的概念
- Positional Encoding（位置编码）—— 为什么要有这个？
- Encoder 里有几层 Transformer / CNN
- Bottleneck 是什么
- Contact Point Head 输出什么（contact point / heatmap？）
- Trajectory Network 用了什么（Transformer → 出 5 个点）
- 每个 Head 的 output 很重要

### 4.4 为什么必须理解网络结构？
因为后续要在 VRB 上**加入语义信息**（semantic input），这是项目的创新点：
- 原 VRB 只有图像输入，模型"看到图就预测动作"
- 但不知道目标是"开柜子"还是"拿里面的东西"
- 加入语义后，可以告诉模型：
  - 目标是什么（杯子 / 柜子 / 罐子）
  - 动作是什么（cut / pull / take）
- 同样的图，不同语义指令 → 不同的 contact point 和 trajectory

## 五、数据集格式确认

### 5.1 最终数据集应该包含

- **Image**：场景图片（224×224 或 150×150 左右）
- **Contact Point**：5 个点的坐标
  - 老师提到不确定是出 contact point 还是 keypoint，需要确认
  - 如果是 contact point → regression 回归模型
  - 如果是 heatmap → 用 cross-entropy loss
  - 但老师倾向于 contact point（回归），因为 heatmap 如果直接预测需要很准
- **Trajectory**：5 个点（不需要画线条，只要 5 个点的坐标）
  - 5 个点的顺序要考虑：是否有顺序？怎么连起来？
  - Transformer 应该是输出 5 个点，然后按顺序连线
- **Narration / Annotation**：动作描述 + 物体名称
  - 从视频 annotation 里提取
  - 切割视频时要注意：这段是切苹果、那段是切香蕉，要对应好

### 5.2 关于 Trajectory Start Point

老师提到要"调整 trajectory 的起始点"（语音识别为 "reject rate"），结合笔记中写的 "Adjust the start point of the trajectory"，说明当时已经在关注 trajectory 的起点问题。
