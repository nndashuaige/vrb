## 一、当前进展

### 1.1 已完成的部分
- Pipeline 基本跑通：能生成一张包含 contact point 和 trajectory 的可视化图
- 但这张图是**手动筛选出来的"好样本"**，不代表批量跑能work

### 1.2 手动筛选的"好样本"标准
学生手动选了一个同时满足以下条件的帧：
- 图里**有目标物体**
- 后续帧**有轨迹**
- 轨迹**比较平稳**
- **没有手**（human-less）
- 能完整跑通 contact point → trajectory 的 pipeline

## 二、核心问题：Pipeline 批量跑不通

### 2.1 现象
- 一个视频约 18,000 帧，分成多个 sub-action（如前 500 帧内有 7 个子动作）
- 但**大部分 sub-action 跑不通 pipeline**，无法稳定产出 contact point + trajectory
- 学生怀疑是**阈值设得太紧**或**筛选逻辑太严格**

### 2.2 Pipeline 环节（逐个排查）
带教要求学生明确每个 sub-action 到底卡在哪一步：

| 步骤 | 检测内容 | 失败表现 |
|---|---|---|
| ① | 手部检测 | 没检测到手 |
| ② | 物体检测 | 没检测到目标物体 |
| ③ | 接触判断 | hand bbox 和 object bbox 没有重叠 |
| ④ | Contact point 提取 | 接触后无法提取 contact point |
| ⑤ | Trajectory 计算 | 后续帧无法算出稳定轨迹 |
| ⑥ | 投影回起始帧 | homography 投影失败 |

**关键任务：逐个 sub-action 排查，定位具体失败环节。**

## 三、重大 Bug 发现：Narration / Annotation 表没有用上

### 3.1 问题发现过程
带教现场打开 EPIC-Kitchens 的 annotation CSV 文件，发现学生**根本没有使用表里的信息**。具体表现：

- 学生做物体检测时**没有输入 object name 作为 prompt**
- 物体检测模型（100DOH）只检测手，不自动知道要检测什么物体
- 学生之前"能做出来"的样本纯属巧合（模型碰巧检测到了 bag）

### 3.2 Annotation 表结构（CSV）
带教现场查看了 CSV，确认有以下字段：

| 字段 | 说明 |
|---|---|
| `narration` | 动作描述，如 "take cup" |
| `verb` | 动词，如 "take" / "open" |
| `noun` | 物体名称，如 "cup" / "fridge" |
| `start_time` / `stop_time` | 动作开始/结束的时间戳 |
| `start_frame` / `stop_frame` | 动作开始/结束的第几帧 |
| `participant_id` / `video_id` | 视频标识 |

### 3.3 正确用法
```
narration: "take cup"
         ↓ 拆分
verb: "take"    noun: "cup"
         ↓            ↓
   (语义输入)    (object detection 的 prompt)
                        ↓
              告诉检测网络："在这帧图里找 cup"
```

**也就是：必须根据 annotation 表里的 `noun` 字段，把物体名称作为 vocabulary / prompt 输入给 object detection 模型，才能稳定检测出目标物体。**

### 3.4 带教的反应
带教对此非常震惊：
> "你这个太扯了，你这个必须太得看了……你不能说它 work 了就不管它了"

要求学生**立刻修正**，这是当前最阻碍进度的问题。

## 四、使用的检测模型

### 4.1 手部检测：100DOH
- 全称：**100 Days of Hands**
- 用途：检测手的位置（hand bbox）
- 特点：**只输出 hand bbox，不输出物体名称**
- GitHub：https://github.com/ddshan/hand_object_detector（或相关 repo）
- 学生确认使用了这个模型

### 4.2 物体检测
- 学生之前用的方法**没有显式输入 object name**
- 带教怀疑是用了某种 **zero-shot / open-vocabulary** 检测器，但学生自己也不清楚原理
- 带教建议确认模型原理，如果不行就换成**显式输入 object name** 的检测方法

## 五、Inpainting（去手）的详细解释

这次会议带教**详细解释了为什么要去掉手**：

> "如果你这个手一直在边上，它就会找那个 shortcut。他会找手边上的话，其实我觉得在手边上那 contact point 应该永远在手的边上，所以不能有这个手。"

### 核心原因：防止网络"走捷径"（Shortcut Learning）

| 情况 | 结果 |
|---|---|
| 训练图里有手 | 网络学到：**contact point 就在手旁边** → 错误 |
| 训练图里无手 | 网络学到：**从物体本身的视觉特征判断 affordance** → 正确 |

### 最终数据要求
- 输入网络的训练图必须是 **human-less**（没有手）
- 图要 **clean**（干净）
- 处理方法：检测手 → 打 mask → inpainting 补全 → 保留该帧

## 六、Pipeline 正确流程（修正后）

```
1. 读取 annotation CSV
   └─ 获取：verb, noun, start_frame, stop_frame
            ↓
2. 按 start_frame ~ stop_frame 切出视频片段（sub-action）
            ↓
3. 对该片段逐帧处理：
   ├─ ① 用 100DOH 检测 hand bbox
   ├─ ② 用 object detection（输入 noun 作为 prompt）检测 object bbox
   ├─ ③ 判断 hand bbox 与 object bbox 是否接触
   ├─ ④ 接触后提取 contact points（GMM 拟合）
   ├─ ⑤ 后续帧提取 hand trajectory
   ├─ ⑥ Homography 投影回 start_frame
   └─ ⑦ 对 start_frame 做 inpainting（去手）
            ↓
4. 输出训练样本：
   └─ {image, heatmap, contact_point, trajectory, annotation}
```
