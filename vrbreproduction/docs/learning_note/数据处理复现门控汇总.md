# 数据处理复现门控汇总

本文按当前复现代码整理，主要对应：

- `notebooks/data_processing_pipeline.ipynb`
- `src/vrbreproduction/contact_point_utils.py`
- `src/vrbreproduction/problem3_runner.py`
- `src/vrbreproduction/problem3_utils.py`
- `src/vrbreproduction/label_heatmap_utils.py`

这里的“门控”指：一帧或一个样本进入后续 pipeline 前，需要满足哪些条件；不满足时会被跳过、标记为 discard，或者只是不生成某个可视化结果。

## 总体理解

当前代码里有四层门控：

1. **Cell 1：论文式 contact frame 定义**
   - 目的是按论文思路找“第一次接触帧”。
   - 它只判断 HOA 标注里的手是否处于接触状态，不检查接触点是否能提出来，也不检查 homography 是否稳定。

2. **Cell 1-测试 / Cell 2：contact point 提取门控**
   - 目的是判断某一帧能不能提取出足够多的接触点。
   - 这是工程预筛选，不等价于论文里的 contact frame 定义。

3. **Cell 3：reference frame、轨迹、homography、几何一致性门控**
   - 目的是判断这个样本能不能被可靠地投影到 human-less reference frame 上。
   - 这一层会筛掉很多“接触点能提出来，但单应性变换不可靠”的样本。

4. **Cell 4：heatmap / arrow 生成前置检查**
   - 目的是避免在已经 discard 或缺少关键变量时继续画热图。
   - Cell 4 通常不重新决定样本是否有效，而是根据前面结果决定是否生成输出。

因此，一个样本通过 Cell 1-测试，只代表它通过了 **contact point 预筛选**，不代表一定能在 Cell 3/4 画出最终轨迹和热图。

## 三种 pipeline 入口模式

Cell 2 现在通过 `pipeline_input_mode` 选择样本来源：

| 模式 | 来源 | 已经过了哪些筛选 | 适合用途 |
|---|---|---|---|
| `manual` | `manual_pipeline_samples` | 没有预筛选，只是手动指定帧和手 | 调试某一帧 |
| `filtered` | Cell 1-测试的 `filtered_pipeline_samples` | 已通过 contact point 数量预筛选 | 先批量跑通工程流程 |
| `paper` | Cell 1 的 `paper_pipeline_samples` | 只满足论文式第一次接触定义 | 严格按论文入口跑 |

注意：`pipeline_sample_index` 是“当前样本组里的第几个样本”，不是视频原始帧号。例如 `pipeline_input_mode='filtered'` 时，`pipeline_sample_index=100` 表示取 `filtered_pipeline_samples[100]`。

## Cell 1：论文式 contact frame 门控

Cell 1 的目标是从 HOA detection 中得到论文式 contact frame。

代码条件：

| 条件 | 当前值 | 直观含义 |
|---|---:|---|
| 手检测分数 | `hand.score > 0.5` | 低置信度的手不参与 contact 判断 |
| 接触状态 | `PORTABLE_OBJECT` 或 `STATIONARY_OBJECT` | 只认为“手正在接触可携带物体或静止物体”是接触 |
| 平滑方式 | Savitzky-Golay, `window_length=7`, `polyorder=2` | 去掉单帧抖动，让 contact 序列更连续 |
| 二值阈值 | `smooth > 0.75` | 平滑后仍然足够像 contact，才算 contact frame |
| 最终选择 | 左右手二值序列里最早出现的 contact frame | 当前视频/片段的论文式第一接触帧 |

保留什么：

- 手检测可信。
- HOA 状态明确表示正在接触物体。
- 接触不是孤立的一帧抖动，而是在平滑后仍然稳定。
- 每个视频/片段最终主要保留第一个接触帧作为论文式入口。

筛掉什么：

- `hand.score <= 0.5` 的低置信度手。
- 手存在但状态不是接触物体的帧。
- 只有一两帧短暂闪现、平滑后达不到 `0.75` 的 contact 噪声。
- 论文式入口不会把所有 contact positive 帧都当成样本。

输出变量：

- `paper_t_contact`
- `paper_active_hand`
- `paper_first_contact_sample`
- `paper_pipeline_samples`
- `paper_positive_contact_samples`

其中 `paper_positive_contact_samples` 只是诊断用，表示所有平滑后为 contact 的帧；它不是当前严格论文入口的批量样本列表。

## Cell 1-测试：contact point 预筛选门控

Cell 1-测试的目标不是重新定义论文 contact frame，而是扫描一批候选帧，找出“接触点提取得出来”的样本。

### 扫描范围门控

代码条件：

| 条件 | 当前值 | 直观含义 |
|---|---:|---|
| 扫描上限 | `scan_limit = 500` | 默认只扫描前 500 帧 |

保留什么：

- 位于 `0 <= frame_idx < min(scan_limit, num_frames)` 范围内的帧。

筛掉什么：

- 超过 `scan_limit` 的帧不会被 Cell 1-测试扫描到。
- 如果想扫完整视频，需要把 `scan_limit` 改成 `num_frames`。

### 候选接触帧门控

代码条件：

| 条件 | 当前值 | 直观含义 |
|---|---:|---|
| 物体检测框 | `obj.score >= 0.5` | 这一帧必须至少有一个可信物体框 |
| 手检测分数 | `hand.score > 0.5` | 低置信度手不作为候选 |
| 手状态 | `PORTABLE_OBJECT` 或 `STATIONARY_OBJECT` | 手必须处于接触物体状态 |
| 每帧处理手数量 | 找到第一个满足条件的手后 `break` | 一帧里只取第一个合格手做测试 |

保留什么：

- 有可信物体框。
- 有可信手。
- 手状态显示正在接触物体。

筛掉什么：

- 没有物体框的帧。
- 有手但手分数太低的帧。
- 有手但状态不是接触物体的帧。
- 同一帧如果第一只合格手失败，代码当前不会继续尝试第二只合格手。

### 接触点提取门控

Cell 1-测试调用 `extract_contact_points()`，当前配置是：

```python
ContactExtractionConfig(
    use_object_mask=True,
    use_object_boundary=True,
    boundary_distance_px=6.0,
    project_points_to_object_boundary=True,
)
```

基础阈值来自 `ContactExtractionConfig`：

| 参数 | 当前值 | 直观含义 |
|---|---:|---|
| `hand_score_threshold` | `0.5` | 手框置信度阈值 |
| `object_score_threshold` | `0.5` | 物体框置信度阈值 |
| `lower_skin_ycrcb` | `(0, 133, 77)` | 皮肤颜色下界 |
| `upper_skin_ycrcb` | `(255, 173, 127)` | 皮肤颜色上界 |
| `object_bbox_shrink_px` | `2` | GrabCut 初始化时略微缩小物体框 |
| `grabcut_iterations` | `3` | GrabCut 迭代次数 |
| `grabcut_bg_margin_px` | `6` | 物体框外扩一圈作为可能背景 |
| `hand_exclusion_dilate_px` | `3` | 把手部皮肤区域膨胀后当作可能背景 |
| `boundary_distance_px` | notebook 中为 `6.0` | 候选点必须靠近物体可见边界 |

提取流程：

1. 根据 active hand bbox 和所有 object bbox 选择一个 active object bbox。
   - 优先选择和手框交集最大的物体框。
   - 再按中心距离等因素打破平局。

2. 在手框内做 YCrCb 皮肤颜色分割。
   - 得到 `hand_skin_mask`。
   - 对皮肤 mask 做一次腐蚀，再用原 mask 减去腐蚀结果，得到 `hand_edge_mask`。

3. 在物体框内估计可见物体区域。
   - 使用 GrabCut 得到 `object_mask`。
   - 手部皮肤区域会被标成可能背景，减少把手内部当成物体的情况。
   - 如果 GrabCut 结果小于 20 个像素，回退成完整物体 bbox mask。

4. 从物体 mask 得到物体边界和边界附近区域。
   - `object_boundary_mask` 是物体边界。
   - `object_boundary_band` 是边界向外膨胀 `boundary_distance_px=6.0` 后的区域。

5. 构造 contact candidate。
   - 原始候选点：`hand_edge_mask` 里的点，并且落在 active object bbox 内。
   - 进一步筛选：如果启用 `use_object_boundary=True`，候选点还必须落在 `object_boundary_band` 内。
   - 最终点：如果启用 `project_points_to_object_boundary=True`，把候选点投影到最近的物体边界上。

最终门控：

| 条件 | 当前值 | 直观含义 |
|---|---:|---|
| 最终 contact points 数量 | `len(contact_points) >= 5` | 至少要有 5 个点，后面才能拟合 5 个 GMM mode |

保留什么：

- 手部皮肤边缘和物体框有空间接近。
- 手部边缘点靠近物体可见边界。
- 最终投影到物体边界上的 contact samples 至少有 5 个。

筛掉什么：

- 看起来有手但皮肤分割几乎没有结果的帧。
- 手边缘和物体 bbox 没有接触或交叠的帧。
- 手边缘点虽然进了物体 bbox，但离可见物体边界太远的帧。
- 最终 contact points 少于 5 个的帧。

Cell 1-测试中的状态名：

| 状态 | 含义 |
|---|---|
| `valid` | 通过 contact point 预筛选，进入 `filtered_pipeline_samples` |
| `discard_contact_points` | 有候选接触帧，但最终 contact points 少于 5 |
| `missing_frame` | 图像文件读不到 |

## Cell 2：单样本 contact point 和 GMM 门控

Cell 2 是后续 Cell 3/4 的单样本入口。它会根据 `pipeline_input_mode` 和 `pipeline_sample_index` 选出一个样本，然后重新做 contact point 提取。

代码条件：

| 条件 | 当前值 | 直观含义 |
|---|---:|---|
| 样本组非空 | 必须有可选样本 | 例如 `filtered` 模式必须先跑 Cell 1-测试 |
| `pipeline_sample_index` 合法 | `0 <= index < len(pipeline_samples)` | 防止取不存在的样本 |
| 图像文件存在 | `frame_{t_contact + 1:010d}.jpg` 能读到 | 注意代码里的 frame 是 0-based，图像文件名是 1-based |
| active hand bbox | `hand.score >= 0.5` 且 side 匹配 | 当前指定的手必须在这一帧能找到 |
| object bbox | `obj.score >= 0.5` | 当前帧必须有可信物体框 |
| contact points 数量 | `len(contact_points) >= 5` | 需要足够点数拟合 GMM |
| GMM mode 数量 | `n_components=5` | 后续 heatmap 使用 5 个 contact mode |

保留什么：

- 当前选择的样本能读到图像。
- 当前 active hand 能找到。
- 当前帧有物体框。
- 重新提取后仍然有至少 5 个 projected contact points。
- 能成功拟合 5-component GMM，得到 `contact_means`、`contact_weights`、`contact_covariances`。

筛掉什么：

- 手动选择或 paper 模式给出的帧虽然是 contact frame，但找不到对应 active hand bbox。
- 没有物体框的帧。
- contact points 少于 5 个的帧。

Cell 2 的 discard reason：

| `discard_reason`                                  | 直观含义                                 |
| ------------------------------------------------- | ------------------------------------ |
| `missing_hand_or_object_bbox`                     | 当前帧缺 active hand bbox 或缺 object bbox |
| `contact_points_lt5_after_object_boundary_filter` | 经过物体边界筛选和投影后，contact points 不足 5 个   |

## Cell 3：reference frame、轨迹、homography 和几何门控

Cell 3 是当前最严格的一层。即使样本通过 Cell 1-测试和 Cell 2，也可能在这里失败。

### 前置门控

代码条件：

| 条件 | 直观含义 |
|---|---|
| 如果 Cell 2 已经 `discard=True`，直接停止 | 前面已经判定不可用，就不继续投影 |
| `contact_means is not None` | 必须有 GMM contact centers |

对应 discard reason：

| `discard_reason` | 直观含义 |
|---|---|
| Cell 2 原因 | 沿用 Cell 2 的失败原因 |
| `missing_contact_means` | 没有 GMM contact centers，无法继续 |

### strict human-less reference frame 门控

代码条件：

| 条件      |                       当前值 | 直观含义                     |
| ------- | ------------------------: | ------------------------ |
| 搜索方向    |     从 `t_contact - 1` 向前找 | 找接触发生前的人手消失帧             |
| 有效手阈值   |       `hand.score >= 0.5` | 可信手才算“有人手”               |
| 连续无手帧长度 |  `min_no_hand_streak = 3` | 必须连续 3 帧都没有可信手           |
| 选择方式    | 返回连续无手段中最靠近 contact 的最后一帧 | reference frame 尽量靠近接触时刻 |

保留什么：

- 接触前存在连续至少 3 帧没有可信手的片段。
- reference frame 相对干净，适合把接触点和轨迹投影过去。

筛掉什么：

- 接触前一直有人手。
- 只有孤立的一帧无手，但前后仍有人手。
- 检测抖动导致无手帧不连续。

对应 discard reason：

| `discard_reason` | 直观含义 |
|---|---|
| `no_strict_humanless_frame` | 找不到连续 3 帧无手的 reference frame |

### 轨迹点门控

代码条件：

| 条件 | 当前值 | 直观含义 |
|---|---:|---|
| 轨迹长度 | `offset in range(6)` | 取 `t_contact` 到 `t_contact + 5` |
| active hand 条件 | `hand.score > 0.5` 且 side 匹配 | 只取当前 active hand 的 bbox center |
| 硬性保留条件 | `len(trajectory_pixels) > 0` | 至少要有一个轨迹点 |

保留什么：

- contact 后至少能找到一个 active hand 轨迹点。

筛掉什么：

- contact 后 6 帧内完全找不到 active hand 的样本。

注意：当前代码允许 6 个 offset 里缺部分轨迹点，只记录在 `trajectory_missing_offsets`。只有一个轨迹点都没有时才 discard。

对应 discard reason：

| `discard_reason` | 直观含义 |
|---|---|
| `missing_trajectory_points` | 接触后没有任何 active hand 轨迹点 |

### pairwise homography 基础门控

Cell 3 会把 contact frame 和每个轨迹帧逐帧累计投影到 reference frame。每一对相邻帧都要先计算 pairwise homography。

动态区域 mask：

| 条件 | 当前值 | 直观含义 |
|---|---:|---|
| 手框排除阈值 | `hand.score >= 0.5` | 手是动态物体，不用于匹配背景 |
| 物体框排除阈值 | `obj.score >= 0.5` | 被操作物体也视为动态区域 |
| bbox 外扩 | `expand_px = 8` | 多排除一圈，避免边缘动态区域污染特征 |

ORB / RANSAC 参数：

| 参数 | 当前值 | 直观含义 |
|---|---:|---|
| ORB 特征数 | `nfeatures=2000` | 尽量找足够背景特征 |
| Lowe ratio test | `0.75` | 去掉不够明确的匹配 |
| RANSAC 重投影阈值 | `5.0` px | 匹配点投影误差需要在可接受范围内 |

基础失败条件：

| 条件 | 状态名 | 直观含义 |
|---|---|---|
| 原始 keypoints 或 descriptors 不足 10 | `insufficient_features` | 画面里可用于匹配的纹理太少 |
| previous frame 经过动态 mask 后特征不足 10 | `insufficient_masked_features_prev` | 去掉手和物体后，上一帧背景特征太少 |
| current frame 经过动态 mask 后特征不足 10 | `insufficient_masked_features_cur` | 去掉手和物体后，当前帧背景特征太少 |
| ratio test 后 good matches 少于 10 | `insufficient_good_matches` | 两帧之间稳定匹配太少，连基础 homography 都不够 |
| `cv2.findHomography` 返回 None | `ransac_failed` | RANSAC 找不到一致的单应性矩阵 |

这些基础失败会在 Cell 3 里表现为：

| `discard_reason` | 直观含义 |
|---|---|
| `pairwise_homography_failed_f{cur}_to_f{prev}` | 某一对相邻帧 homography 直接算不出来 |

### pairwise homography 质量门控

即使 homography 能算出来，还必须过质量阈值：

| 条件 | 当前阈值 | 直观含义 |
|---|---:|---|
| good matches | `>= 60` | 可用匹配点数量要足够多 |
| RANSAC inliers | `>= 40` | 被 RANSAC 认为一致的点要足够多 |
| inlier ratio | `>= 0.45` | 匹配里至少 45% 要支持同一个几何变换 |

保留什么：

- 背景纹理足够。
- 相邻帧之间运动不太剧烈。
- RANSAC 找到的几何变换稳定。

筛掉什么：

- 手和物体遮挡太多，背景特征不足。
- 画面模糊、快速运动、视角变化大。
- 匹配点虽然有一些，但数量没有达到当前质量阈值。
- 某一对相邻帧不过关，整个样本都会 discard。

对应 discard reason：

| `discard_reason` | 直观含义 |
|---|---|
| `pairwise_homography_low_quality_f{cur}_to_f{prev}` | homography 算出来了，但 good matches / inliers / ratio 至少有一项没过质量阈值 |

直观例子：

- 如果某一对帧是 `good_matches=59, inliers=58, inlier_ratio=0.98`，它仍然会失败。
- 原因不是 RANSAC 比例差，而是 `good_matches < 60`，差 1 个匹配点也会触发 `pairwise_homography_low_quality_*`。

### 接触点投影门控

代码条件：

| 条件 | 直观含义 |
|---|---|
| `H_contact_to_ref` 必须存在 | contact frame 必须能投影到 reference frame |
| `transform_points(contact_means, H_contact)` 不能返回 None | 5 个 contact means 必须能被变换到 reference frame |

对应 discard reason：

| `discard_reason` | 直观含义 |
|---|---|
| `missing_transformed_contact_points` | contact means 无法变换到 reference frame |

### 物体几何一致性门控

代码条件：

| 条件 | 当前值 | 直观含义 |
|---|---:|---|
| active hand bbox | score threshold `0.5` | contact frame 上还要能找到 active hand |
| object bbox | score threshold `0.5` | contact frame 上还要能找到 object |
| 投影后物体面积 | `projected_area > 0` | 物体 bbox 投影后不能翻折成无效区域 |
| 面积比例 | `area_ratio >= 0.15` | 投影后的物体不能严重塌缩 |
| contact means 在物体附近数量 | `inside_count >= 4` | 5 个 contact means 至少 4 个要在物体区域内或附近 |
| 物体附近容忍距离 | `tolerance_px = 8.0` | 允许 contact point 在物体外 8 px 内 |
| contact centroid 距离 | `centroid_dist >= -8.0` | contact 中心不能明显跑到物体外面 |

保留什么：

- contact points 投影后仍然落在被操作物体附近。
- 物体 bbox 投影到 reference frame 后形状合理。
- contact cluster 的整体中心仍然贴着物体。

筛掉什么：

- homography 把物体框投影到奇怪位置或严重压缩。
- contact points 被投影到物体外很远。
- 单个点可能还能容忍，但整体中心已经明显偏离物体的样本。

对应 discard reason：

| `discard_reason` | 直观含义 |
|---|---|
| `no_active_object_bbox` | contact frame 找不到可用 active object bbox |
| `projected_object_polygon_invalid` | 物体框投影后面积无效或塌缩过严重 |
| `transformed_contact_points_off_object` | 5 个 contact means 中少于 4 个在物体区域内或 8 px 附近 |
| `transformed_contact_centroid_off_object` | contact points 的中心明显跑到物体外 |

### 图像边界门控

代码条件：

| 条件 | 直观含义 |
|---|---|
| 每个 transformed trajectory point 都要在 reference frame 图像范围内 | 轨迹不能被投影到画面外 |
| 每个 transformed contact mean 都要在 reference frame 图像范围内 | 接触点不能被投影到画面外 |

对应 discard reason：

| `discard_reason` | 直观含义 |
|---|---|
| `trajectory_out_of_bounds_t+{i}` | 第 `i` 个轨迹点投影后越界 |
| `contact_point_out_of_bounds_mu_{i+1}` | 第 `i+1` 个 contact mean 投影后越界 |

## Cell 4：heatmap 和 arrow 输出门控

Cell 4 不再重新筛样本，主要根据 Cell 2/3 的结果决定是否生成可视化。

### heatmap 前置检查

代码条件：

| 条件 | 直观含义 |
|---|---|
| 如果 `discard=True`，跳过 heatmap | 前面已经判定样本不可用 |
| `mu_transformed` 必须存在 | 热图中心必须在 reference frame 坐标系下 |
| `ref_idx` 必须存在 | 必须知道热图画在哪一帧 |
| reference frame 图像必须能读到 | 图像文件缺失会直接报错 |

### covariance heatmap fallback

Cell 4 默认：

| 参数 | 当前值 |
|---|---:|
| `heatmap_mode` | `covariance` |
| `covariance_scale` | `6.0` |
| `min_sigma_px` | `7.0` |
| `max_sigma_px` | `40.0` |
| isotropic fallback `sigma_px` | `12.0` |
| `merge_method` | `sum` |

如果缺少 `contact_covariances`、`contact_means` 或 `H_contact_to_ref`，代码会自动退回 `isotropic` 圆形高斯热图。这个 fallback 不会把样本 discard，只会改变热图生成方式。

### VRB-style arrow 门控

代码条件：

| 条件 | 当前值 | 直观含义 |
|---|---:|---|
| 有效轨迹点数量 | 至少 2 个 | 至少要有起点和终点才能画方向 |
| 最小运动幅度 | `min_motion_px = 1.0` | 轨迹几乎不动时不画箭头 |
| arrow anchor | 优先 `contact_centroid`，否则 `mu_transformed` 均值 | 箭头从接触热区中心出发 |

如果不满足这些条件，Cell 4 会打印“VRB-style arrow 未生成”，但 heatmap 仍然可以生成。

## 当前代码里最关键的区别

1. **Cell 1 是论文式 contact frame 定义。**
   - 它关心“什么时候第一次接触”。
   - 它不保证后续 contact point、homography、heatmap 都能成功。

2. **Cell 1-测试是工程预筛选。**
   - 它关心“这一帧能不能提取出至少 5 个接触点”。
   - 它不保证 Cell 3 的 homography 质量一定过关。

3. **`filtered_pipeline_samples` 只通过了 contact point 预筛选。**
   - 它适合用于先批量跑通流程。
   - 如果某个样本后续画不出轨迹，通常要看 Cell 3 的 `discard_reason`。

4. **homography 是后续最常见的严格门控。**
   - 只要从目标帧回到 reference frame 的任意一对相邻帧质量不过，整个样本就会被丢弃。
   - 当前质量阈值是 `good_matches >= 60`、`inliers >= 40`、`inlier_ratio >= 0.45`。

5. **手动模式和 paper 模式不会自动绕过门控。**
   - 它们只是换了样本入口。
   - Cell 2/3 仍然会按同一套规则筛掉不合格样本。

## 一句话总结

当前 pipeline 的筛选逻辑可以理解为：

> 先用论文式规则或手动/预筛选方式选一个 contact 样本；再检查这帧能不能提取至少 5 个靠近物体边界的接触点；然后检查接触点和手轨迹能不能通过稳定 homography 投影到干净 reference frame；最后只有未 discard 且变量齐全的样本才生成 heatmap 和 VRB-style arrow。
