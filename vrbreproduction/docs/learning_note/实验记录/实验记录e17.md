# e17 2026-5-28

## 一、E17 实验设计思路

E17 是在 E16 的基础上做的一个更直接的诊断实验，核心问题只有一个：

> 如果 reference frame 不再要求 humanless，也不再要求 active hand invisible，而是直接贴近 first contact 去选，会不会显著提高最终可用样本数？

E15 和 E16 都已经说明，reference selection 是重要瓶颈：

- E15 使用 strict global no-hand，结果太差；
- E16 改成 active-hand-invisible 后，`final keep` 从 `14` 提升到 `26`；
- 但 E16 仍然存在大量 `no_active_hand_invisible_reference`，说明 reference 规则还是偏严。

因此 E17 不再试图“贴近论文语义”，而是故意做一个 near-contact diagnostic baseline：

- 不要求 strict humanless；
- 不要求 active hand invisible；
- 不要求 E14 clean pre-contact gate；
- 只问一件事：如果 reference 就放在 first contact 前 `5-10` 帧里，当前 homography pipeline 能不能明显更稳定？

这个实验的目的不是做最终 paper-faithful baseline，而是定位问题：

1. 如果 E17 大幅提升，说明 E15/E16 的主要问题真的是 reference 太远、太严格；
2. 如果 E17 仍然提升有限，说明真正的上限主要还是被 Cell2/contact tuple 和 geometry gate 卡住。

## 二、E17 改了什么

E17 新增脚本：

```text
src/vrbreproduction/e17_near_contact_reference.py
```

正式输出目录：

```text
outputs/e17
```

Smoke 输出目录：

```text
outputs/e17_smoke10
```

E17 保留了 E16 的主体结构：

- `video_id = P01_109`
- 前 `100` 个 EPIC annotations
- 一个 subaction 最多输出一个 final tuple
- 每个 subaction 只取第一个 new contact run
- candidate frame 固定为该 run 的 start frame，也就是 `t0`
- 不尝试 `t0+1/t0+2`
- Cell2 contact extraction / GMM 不改
- Cell3 homography + geometry gate 不改
- Cell4 heatmap generation 不改
- trajectory 逻辑不改

E17 的核心改动只在 reference construction：

| 项目 | E16 | E17 |
| --- | --- | --- |
| 主 reference | active hand invisible | near-contact pre-frame |
| reference 搜索范围 | episode 前回溯最多 360 帧 | `t0-5` 到 `t0-10` |
| 是否要求 active hand 不可见 | 是 | 否 |
| 是否要求 strict no-hand | 否（shadow only） | 否（shadow only） |
| 是否要求 E14 clean gate | 否 | 否 |
| 是否允许跨 annotation 边界向前找 | 本质上允许 | 允许 |

E17 的 reference mode 为：

```text
near_contact_pre_frame
```

reference 选择顺序是：

```text
offset = 5, 6, 7, 8, 9, 10
```

也就是说，优先用 `t0-5`；如果帧不存在，再试 `t0-6`，以此类推。第一个可用帧就是 reference。

注意：

> E17 不是 paper-faithful baseline，而是 near-contact diagnostic baseline。

## 四、E17 和 E16 的核心差异

E16 的问题是：

> reference 必须是 active hand 不可见的 pre-contact frame。

这会导致很多样本虽然 contact frame 本身是好的，Cell2 也能过，但因为接触前始终看得到 active hand，所以直接失败。

E17 则完全绕过这个语义限制：

> reference 只要是 first contact 前 `5-10` 帧里的一个真实存在帧就可以。

这带来三个直接后果：

### 1. reference 找到率大幅提高

E16：

- `ref_found = 38`

E17：

- `ref_found = 81`

这基本说明：在这 81 个 new-contact subaction 里，reference 不再是问题。

### 2. homography path 明显变短

E16 的 keep 样本 `median reference_anchor_gap = 13`，而且很多失败样本的 gap 更远。

E17 的 keep 样本：

- `median reference_anchor_gap = 5`
- `median ref_gap = 5`

这意味着 contact frame 到 reference frame 的逐帧链路通常只有 5 步左右，而不是十几步甚至几十步。链越短，pairwise homography 失败概率越低。

### 3. 最终 keep 大幅增加

E16 的 `final keep = 26`，E17 变成 `47`。

这个提升不是靠放松 geometry gate 获得的，因为：

- Cell2 没改；
- Cell3 pairwise quality gate 没改；
- geometry gate 没改；
- heatmap 逻辑没改。

真正改变的是：

> 让更多 Cell2 已经合格的样本，能找到一个更近、更稳定的 reference，从而把 homography 链打通。

## 五、E17 的真实漏斗

E17 的真实漏斗是：

| 阶段 | 剩余 |
| --- | ---: |
| 100 subactions | 100 |
| 有 new-contact candidate | 81 |
| Cell2 contact/GMM pass | 59 |
| reference found | 81 |
| homography available | 52 |
| final keep | 47 |

这张漏斗最关键的结论是：

### 1. reference 问题被基本排掉了

E17 里 `ref_found = 81`，和 `new-contact candidate = 81` 一样，说明：

> 只要有 new-contact episode，E17 几乎总能构造出 reference。

所以 E15/E16 的低通过率，确实很大一部分来自 reference 选择过远、过严。

### 2. 当前 pipeline 的主上限已经暴露出来

虽然 reference 已经不再是主要问题，但 `Cell2 pass` 仍然只有 `59`。

也就是说，就算 reference、homography、geometry 后面全部 100% 成功，E17 当前 pipeline 的理论上限也还是只有：

```text
59 / 100
```

所以如果目标是逼近论文式的 `80/100` 量级，单靠 reference 优化已经不够了。

## 六、主要失败原因

E17 的主要失败原因：

| fail_reason | count |
| --- | ---: |
| continuation_contact_run | 18 |
| contact_points_lt5_after_object_boundary_filter | 11 |
| missing_hand_or_object_bbox | 11 |
| trajectory_out_of_bounds_t+0 | 3 |
| pairwise_homography_low_quality_f630_to_f629 | 2 |
| pairwise_homography_failed_f4385_to_f4384 | 2 |
| pairwise_homography_low_quality_f93_to_f92 | 1 |
| pairwise_homography_low_quality_f161_to_f160 | 1 |
| trajectory_out_of_bounds_t+1 | 1 |
| pairwise_homography_low_quality_f779_to_f778 | 1 |
| no_contact_candidate | 1 |
| contact_point_out_of_bounds_mu_5 | 1 |

按阶段理解：

### 1. `continuation_contact_run = 18`

这 18 个 subaction 的问题不是 reference，也不是 homography，而是：

> 该 subaction 内虽然有接触，但接触 run 是从 subaction 开始前就已经持续下来的，不是新的 `0 -> 1` contact run。

由于 E17 和 E16 一样，坚持“只保留 subaction 内第一个 new contact run”，所以这些样本直接排除。

### 2. `contact_points_lt5_after_object_boundary_filter = 11`

这些样本在 contact frame 上有手和物体，但当前 Cell2 提取到的接触点太少，达不到固定 5-component GMM 的门槛。

这说明当前上限的重要来源仍然是 contact tuple 生成，而不是 reference。

### 3. `missing_hand_or_object_bbox = 11`

这些样本连 contact frame 上的 active hand bbox 或 object bbox 都不稳定，导致 Cell2 直接失败。

### 4. Cell3 剩余失败已经不多

E17 中，reference 已找到且 Cell2 已通过之后，Cell3/geometry 只剩少量失败：

- 某些 pairwise homography 质量不足；
- 少量 trajectory 出界；
- 极少数 contact point 投影出界。

这说明：

> 在 near-contact reference 条件下，Cell3 已经不再是第一瓶颈。

## 七、E17 的意义

E17 给出了一个非常明确的诊断结论：

### 结论 1：E15/E16 的主要问题之一确实是 reference 太远、太严格

这是 E17 最大的贡献。

把 reference 从：

- strict humanless
- active-hand-invisible

改成：

- first contact 前 `5-10` 帧最近可用帧

以后，结果从 `26` 一下提高到 `47`。这个提升幅度足够说明问题。

### 结论 2：reference 不是全部问题

E17 虽然已经显著提升，但仍然没有接近 `80/100`。

原因很清楚：

- `new-contact candidate = 81`
- `Cell2 pass = 59`
- `final keep = 47`

也就是说：

> 当前 pipeline 就算 reference 几乎全找到，仍然会在 Cell2 先损失 22 个，再在后续 geometry/homography 损失一部分。

### 结论 3：如果后续想做 E18，重点不该继续放在 reference 上

E17 已经把 reference 问题几乎打满了。

下一步更值得做的是：

1. 改 contact frame / contact tuple 生成；
2. 改 Cell2 的接触点提取稳定性；
3. 重新思考 subaction 边界和 `continuation_contact_run` 的处理；
4. 在不改变当前 homography 方法的前提下，提高 contact label 质量。

## 九、最终结论

E17 说明了两件事：

### 第一，reference 贴近 contact 非常重要

这部分已经有了明确证据。E16 到 E17 的跃升，不是偶然波动，而是系统性改善。

### 第二，E17 不是最终方案

E17 是一个 near-contact diagnostic baseline，不是最终高质量、paper-faithful 的训练数据构造方法。

因为它虽然把 reference 问题基本排掉了，但没有解决：

- Cell2 只剩 59 个；
- continuation contact 仍损失 18 个；
- 当前接触点生成方式依赖 HOA bbox + skin/object-boundary heuristic；
- 最终上限依然离论文量级有距离。

所以 E17 最重要的作用不是“作为最终答案”，而是：

> 证明 reference 选择确实是 E15/E16 的主要瓶颈之一；但在 reference 解决后，下一步真正该做的是 contact tuple / Cell2 改进，而不是继续只调 reference。
