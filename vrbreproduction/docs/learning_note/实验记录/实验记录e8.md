# e8 2026-5-19

## 一、E8 实验目标

E8 的目标是继续解决 E3-E7 中两个核心问题：

1. contact point（接触点）从接触帧投影到 reference frame（参考帧）时容易歪。
2. 最终可用 subaction（子动作片段）数量不够，E7 只有 `43/100` 个 subaction 成功。

E3-E6 的主线主要围绕 background homography（背景单应性）和 crop / bbox 规则做修正，但这个方向本质上是在问“背景怎么动”。对于 VRB 当前任务，更关键的问题不是背景运动，而是目标物表面本身如何从 contact frame 回到 reference frame。特别是手持物体、移动物体、开合物体、遮挡物体时，背景 homography 无法代表目标物表面运动。

因此 E8 不再继续优化 background homography，而是改成：

> SAM2 object mask + CoTracker object point tracking + mask-based projection gate

也就是直接问：

> 目标物上的点，怎么从接触帧跟踪回参考帧？

## 二、E8 与之前实验的主要区别

### 1. 与 E3-E6 的区别

E3-E6 主要依赖全局或局部几何补偿：

- background homography 用于估计相机 / 背景运动；
- bbox-relative 用目标框相对位置近似 contact point 的迁移；
- crop-level humanless fallback 用局部无人手区域来增加候选；
- reference-frame object consistency 用参考帧检测框收紧质量。

这些方法的问题是：

- background homography 对会移动的目标物不适用；
- bbox-relative 假设物体局部结构稳定，但对 deformable object 和 articulated object 风险较高；
- crop 无手不等于目标物投影正确；
- 单帧 reference object detection 缺失会导致大量 unknown 或 reject。

E8 的变化是把投影目标从“背景 / bbox 几何”改成“目标物 mask 上的可跟踪点”：

- 在 contact frame 上先得到目标物 mask；
- 从目标物 mask 内采样 object points；
- 将 object points 反向跟踪到 reference frame；
- 用 tracked object points 拟合 weighted affine；
- 把 5 个 contact GMM center 投影到 reference frame；
- 最后用 reference object mask 做 mask gate。

### 2. 与 E7 的区别

E7 已经放弃 background homography，改成 object-centric projection（面向物体的投影），但它仍主要依赖：

- active object bbox；
- sparse / local optical flow；
- tracked reference object bbox；
- bbox gate / tracked object gate。

E7 的成功覆盖是：

- subaction success：`43/100`
- final tuple count：`43`

E7 的主要失败原因包括：

- `reference_crop_hand_overlap_high`
- `missing_hand_or_object_bbox`
- `track_confidence_below_threshold`
- `contact_points_lt5_after_object_boundary_filter`
- `projected_contact_not_on_tracked_object`

E8 的核心区别是：

- object 表示从 bbox 升级为 mask；
- tracking 点从 bbox / local sparse flow 升级为 mask 内 object points；
- projection 从 local flow / bbox-relative 改成 tracked object points 的 weighted affine；
- final gate 从 bbox gate 改成 mask gate；
- 每个 subaction 不再只保留 1 个 tuple，而是最多保留 3 个高分 tuple，并做近邻帧去重。

## 三、E8 方法设计

### 1. candidate 选择

E8 沿用 E7/E6 的新接触语义：

- 只处理 smoothed contact 从 0 到 1 的 new contact episode；
- candidate 只取新接触开始附近：`t0`、`t0+1`、`t0+2`；
- reference frame 优先从当前接触 episode 之前的 pre-contact gap 中找；
- 不再为了数量随便回退到很久以前的 full previous reference。

这样做的目的是避免把 continuation contact 当成新的训练样本，也避免 reference frame 与当前接触状态相距太远。

### 2. contact frame 目标物 mask

E8 新增统一接口：

```python
get_object_mask(frame_idx, image_bgr, active_object_bbox, noun, config)
```

mask 来源优先级设计为：

1. VISOR mask；
2. SAM2 box-prompt object mask；
3. GrabCut fallback；
4. bbox fallback。

本次正式跑通结果中，因为本地 SAM2 checkpoint 下载 / 初始化不稳定，实际主要使用了：

- `grabcut_fallback`
- `bbox_fallback`

这点需要在结果解释中单独标注：当前 E8 是方法结构跑通版，不是真正完整的 SAM2 质量上限版本。

### 3. mask 内采样 object tracking points

E8 新增：

```python
sample_object_points_for_tracking(object_mask, contact_means, hand_bbox, config)
```

采样策略：

- 从 object mask 内采样 20-50 个点；
- 优先采样 contact GMM 附近；
- 优先采样 object boundary 附近；
- 排除 active hand bbox 附近区域，减少跟踪到手上的风险；
- 点不够时再从 object interior 补点；
- 每个点记录来源，例如 contact-near / boundary / interior。

注意：可视化图里看到的很多小点不是最终 contact point，而是 object tracking points。最终 contact point 仍然是 5 个 GMM center。

### 4. 5 个 GMM center 仍作为最终 contact 表示

E8 没有取消 contact GMM。流程仍然是：

1. 从接触区域收集 contact points；
2. 拟合 `5` component GMM；
3. 得到 5 个 GMM means；
4. 将这 5 个 GMM center 投影到 reference frame；
5. 基于投影后的 5 个 center 生成 heatmap 和最终训练样本。

所以图上出现很多点时，需要区分两类点：

- 5 个 GMM center：最终 contact point 表示；
- 多个 mask tracking points：用于估计目标物从 contact frame 到 reference frame 的运动。

### 5. 点跟踪与投影

设计接口：

```python
track_object_points_to_reference(frame_indices, points_xy, config)
estimate_contact_projection_from_tracks(contact_means, src_points, ref_points, visibility, config)
```

目标方法是 CoTracker：

- 输入 contact frame 到 reference frame 的帧序列；
- 跟踪 mask 内 object points；
- 输出 reference frame 上的 tracked points、visibility、confidence；
- 再用可见点拟合 weighted affine；
- 权重按距离 contact centroid 越近越高；
- 通过 RANSAC 估计 affine；
- 用 affine 投影 5 个 GMM center。

本次正式运行环境中 CoTracker 未安装，因此实际 `tracker_backend` 是：

- `fallback_lk`

也就是说当前结果没有冒充 CoTracker 成功。CSV 中记录了真实 backend。

### 6. reference frame mask gate

E8 新增：

```python
get_reference_object_mask(ref_idx, ref_image, tracked_points, noun, config)
mask_based_projection_gate(projected_contact_means, reference_object_mask, config)
```

gate 逻辑从 E7 的 bbox / tracked object gate 改成 mask gate：

- 至少 3/5 个 projected GMM center 在 reference object mask 内，或距离 mask boundary 足够近；
- projected contact centroid 不能离 reference object mask 太远；
- visible tracked points 数不能太少；
- affine inlier ratio 不能太低。

记录的关键字段包括：

- `mask_source_contact`
- `mask_source_reference`
- `tracker_backend`
- `projection_method`
- `track_point_count`
- `visible_point_count`
- `affine_inlier_count`
- `affine_inlier_ratio`
- `affine_median_residual`
- `projected_contact_inside_mask_count`
- `projected_contact_to_mask_distance`
- `articulated_object`
- `final_quality_score`

## 四、E8 期望解决的问题

E8 主要希望解决下面几类 E7 中暴露的问题。

### 1. contact point 投影歪

E7 的 local flow / bbox-relative 仍然容易把 contact point 投影到物体外面，尤其在目标物移动、局部遮挡或手部干扰时。

E8 用 mask 内 object points 来估计目标物运动，目标是让 projected contact 更贴近 reference frame 中真实目标物表面。

### 2. bbox 太粗导致 gate 不可靠

bbox 只能表示矩形区域，不能表达物体真实轮廓。对于细长物体、手和物体重叠、背景相近的情况，bbox gate 会出现：

- 误放行：点在 bbox 内但不在物体上；
- 误拒绝：点靠近真实物体边界但不在粗糙 tracked bbox 内。

E8 改为 mask gate，用物体轮廓判断 projected contact 是否合理。

### 3. reference crop hand overlap 高

E7 中 `reference_crop_hand_overlap_high` 是主要失败原因之一。E8 不再以 crop 是否无人手作为最终核心条件，而是看 projected contact 是否落在 reference object mask 上，希望减少这类失败。

### 4. subaction 覆盖数量不足

E7 成功覆盖 `43/100`，距离目标 80/82 仍差很多。E8 通过：

- mask object 表示；
- mask 内点跟踪；
- mask gate；
- 每个 subaction 最多导出 3 个 tuple；

来提高最终可用样本数量。

## 八、当前结论

E8 验证了从 E7 的 bbox / local flow gate 转向 mask-point tracking + mask gate 是有效方向。在 fallback 环境下，E8 已经把覆盖数量从 E7 的 `43/100` 提升到 `60/100`，final tuple 从 `43` 提升到 `131`。

但当前结果还不是 E8 设计的完整上限，因为：

- CoTracker 没有实际启用，当前 `tracker_backend` 是 `fallback_lk`；
- SAM2 没有稳定接入，当前主要依赖 `grabcut_fallback` 和 `bbox_fallback`；
- articulated object 仍有明显风险；
- `missing_hand_or_object_bbox` 和 `contact_points_lt5_after_object_boundary_filter` 仍是主要瓶颈。

下一步如果要继续推进，应优先做：

1. 正式安装并验证 CoTracker，使 `tracker_backend` 真正变成 `cotracker`；
2. 稳定 SAM2 checkpoint，本地缓存模型，避免运行时下载失败；
3. 对 `contact_points_lt5_after_object_boundary_filter` 做诊断，确认是 contact annotation 稀疏、mask 太小，还是 hand exclusion 过强；
4. 对 articulated object 单独看 contact sheet，评估 mask gate 是否误放行开合类物体。
