# e12 2026-5-20

## 一、E12 实验设计思路

E12 不是继续增强 E11 的 inpainting，而是把问题往前移到 reference frame selection（参考帧选择）阶段解决。

E10 已经把最关键的投影问题基本跑通：

- 覆盖 `79/100` 个 subaction；
- final tuple `157`；
- `tracker_backend = cotracker`，不是 `fallback_lk`；
- contact point / heatmap / trajectory 投影整体比较准；
- part-aware gate 能保证 projected contact 仍然落在 reference frame 的 contact part 上。

但 E10 仍然有一个明显问题：

> reference frame 里经常已经有手，而且手往往已经靠近、压住或者遮挡了后续要操作的目标物体。

E10 里虽然有 `reference_hand_overlap_ratio`，但它只是 sample score 的一个扣分项，不是主要选择目标。所以 E10 经常会选到 `contact_frame - 1` 或非常接近 contact 的帧。这些帧投影通常很好，但目标物体旁边已经有手，甚至 contact part 已经被手盖住。

E11 尝试在 E10 已经选好的 reference frame 上做 bbox mask + OpenCV inpaint。这个思路的问题是：

- 如果手只是远离目标物体，inpaint 可以作为轻量后处理；
- 但如果手已经和目标物体接触，甚至遮挡 contact part，直接擦手会把目标物体也擦坏；
- 物体变形以后，训练图虽然“看起来没有手”，但物体语义反而更差。

因此 E12 的核心判断是：

> 与其在手已经压住目标物体以后强行擦手，不如在 source selection 阶段尽量选择“手还没有接触目标物体”的 reference frame。

E12 要解决的问题不是“怎样把手修得更自然”，而是：

> 在保持 E10 投影准确性和数据量基本不掉的前提下，让 reference frame 更 target-aware、更 clean，减少训练图中的手部 shortcut。

## 二、E12 要解决什么问题

E12 主要解决 E10/E11 暴露出来的 3 个问题。

### 1. E10 只知道投影好，不知道目标物体是否干净

E10 的 reference 选择主要看：

- CoTracker 是否成功；
- local affine 是否稳定；
- projected contact 是否还在 reference object / contact part 上；
- trajectory 是否能生成；
- sample score 是否高。

这保证了投影准确，但没有强烈区分：

- reference frame 上有没有手；
- 手是否遮挡目标物体；
- 手是否遮挡 future contact part；
- 目标物体是否仍然清楚可见。

因此 E10 会保留很多“投影正确但训练图不干净”的样本。

### 2. E11 的后处理不能修复接触遮挡

E11 不改变 E10 的 reference selection，只是在最终输出上做：

- hand bbox mask；
- OpenCV Telea inpaint；
- 保存 `reference_frame_dehanded.png` 和 `hand_mask.png`。

这对“手远离目标”的样本有一定帮助，但对“手压住物体 / contact part”的样本效果不好。原因是 hand bbox 和 object/contact part 已经重叠，inpainting 会同时破坏目标物体。

所以 E11 的结果说明：

> inpainting 不能作为主方法，至少不能在 reference 已经被严重遮挡时作为主方法。

### 3. 训练目标需要 human-less / human-agnostic reference

会议记录里反复强调：训练图里如果有手，模型容易学 shortcut：

> contact point 永远在手边上。

VRB 希望模型从物体本身的视觉结构预测 affordance，而不是看手的位置。因此 reference frame 最理想的状态是：

- contact frame 之前；
- 目标物体可见；
- 目标物体就是后续要操作的那个物体；
- projected contact point / heatmap / trajectory 仍然准确；
- 手不在目标物体和 contact part 附近；
- 如果全图有手但远离目标物体，可以接受；
- 如果手遮挡目标物体或 contact part，应优先换 reference，而不是硬擦。

## 三、E12 用了什么办法

E12 基于 E10 新建：

```text
src/vrbreproduction/e12_target_aware_clean_reference_projection.py
```

它没有覆盖 E10，也没有放松 E10 的 projection gate。

E12 的核心改动在：

```python
evaluate_reference_candidates(...)
```

整体思路是：

> 先保留 E10 的投影正确性约束，再在所有通过 gate 的 reference candidate 中，用 target-aware clean score 重新排序。

### 1. E10 的投影约束全部保留

E12 仍然要求：

- candidate 优先来自 `new_contact_episode`；
- `continuation_entry_rescue` 只作为保守边界补救；
- contact frame 上先确定 active object；
- contact point 仍然来自 hand-object contact 区域的 5 个 GMM center；
- tracking points 仍然优先来自 `contact_part_mask`；
- 使用真实 CoTracker；
- local affine / inlier ratio / median residual 必须合格；
- projected contact 必须通过 part-aware gate；
- trajectory 仍然是 post-contact active hand / wrist trajectory；
- 不回到 background homography；
- 不靠简单放宽 threshold 刷数量；
- 不把 `fallback_lk` 冒充成 CoTracker。

也就是说，E12 不是用“更干净”替代“投影正确”，而是在“投影正确”之后再选择更干净的 reference。

### 2. 新增 target-aware cleanliness 指标

E12 对每个通过投影 gate 的 reference candidate 计算：

- `reference_global_hand_count`
- `reference_hand_area_ratio`
- `reference_object_hand_overlap_ratio`
- `reference_contact_crop_hand_overlap_ratio`
- `reference_contact_part_hand_overlap_ratio`
- `reference_hand_to_object_distance`
- `reference_hand_to_contact_part_distance`
- `reference_target_visible_score`
- `reference_clean_class`
- `reference_clean_score`
- `reference_selection_tier`

这些指标的目的不是简单判断“全图有没有手”，而是判断：

> 手是否真的影响目标物体和 future contact part。

如果图里有手，但手远离目标物体，那么它不应该被当成严重坏样本。如果手压住 object mask 或 contact part，就应该降级。

### 3. 新增 clean class

E12 将 reference candidate 分为 5 类：

| clean class | 含义 | 优先级 |
| --- | --- | --- |
| `strict_target_handless` | 全图无有效 hand bbox，目标物体可见，投影通过 | 最高 |
| `local_target_clean` | 图里可以有手，但目标物体 / contact part / crop 附近无手 | 高 |
| `hand_visible_target_not_occluded` | 有手，但没有明显遮挡目标物体或 contact part | 中 |
| `target_partially_occluded` | 手与目标物体有一定重叠，但 contact part 没有严重覆盖 | 低 |
| `target_occluded_by_hand` | 手明显覆盖 object mask 或 contact part | 最低 |

这套分类比 E10 的 `reference_hand_overlap_ratio` 更细，因为它区分了：

- 全图有手；
- 手在 crop 内；
- 手遮挡 object；
- 手遮挡 contact part；
- 手离目标物体还有多远。

### 4. 选帧 score 改成 projection + clean

E10 的 score 主要是 projection quality、tracking confidence、inside count、gap penalty 和较弱 hand overlap penalty。

E12 改成：

```text
sample_score = projection_score + clean_score - gap_penalty
```

其中：

- `projection_score` 来自 E10 原来的跟踪 / 投影 / part gate 质量；
- `clean_score` 由 `reference_clean_class` 和遮挡指标决定；
- `gap_penalty` 仍然保留，避免无节制选太早的 reference。

这样会让 E12 更愿意选择：

> 稍早一点、但目标物体更干净的 reference frame。

而不是总是选择：

> 离 contact frame 最近，但手已经压住目标物体的帧。

## 四、E12 流程是什么样的

E12 的完整流程可以概括为 9 步。

### 1. 找 candidate contact frame

沿用 E10：

- 优先取 `new_contact_episode`；
- 如果一个 subaction 完全没有 new contact episode，才使用 `continuation_entry_rescue`。

### 2. 在 contact frame 上选 active object

用 hand-object detection 和 contact points 选择当前 hand 正在操作的目标物体。

### 3. 提取 contact points 并拟合 GMM

从 hand-object contact 区域提取 contact points，再拟合 5 个 GMM center。

这 5 个 center 仍然是最终 contact heatmap 的核心表示。

### 4. 构造 contact object mask 和 contact part mask

沿用 E10 的：

- `get_object_mask(...)`
- `build_contact_part_mask(...)`

并结合 noun-conditioned soft prior。

### 5. 用 CoTracker 跟踪 contact-part points

优先从 contact part 区域采样 tracking points，再用 CoTracker 反向跟踪到 reference frame。

### 6. 用 local affine 投影 contact GMM centers

根据 tracked local points 拟合 affine，把 contact frame 上的 5 个 GMM center 投影到 reference frame。

### 7. 做 part-aware projection gate

仍然要求 projected contact 落在 reference object/contact part 上。

这是 E12 的硬约束，不能为了 clean frame 放松。

### 8. 对通过 gate 的 reference candidate 做 cleanliness 评分

计算 hand mask、object mask、contact crop、contact part 之间的重叠和距离，并得到：

- clean class；
- clean score；
- selection tier。

### 9. 按 target-aware score 选择最终 reference

所有通过投影 gate 的 reference candidate 中，选：

```text
projection_score + clean_score - gap_penalty
```

最高的那个。

最终仍然生成：

- `reference_frame.png`
- `label_heatmap_overlay.png`
- `vrb_style_affordance.png`
- `mask_projection_overlay.png`
- CSV diagnostics 和 manifest。

## 七、与 E10 / E11 的效果对比

### 1. 覆盖率和 tuple 数量

| 实验 | 覆盖 subaction | final tuple | 说明 |
| --- | ---: | ---: | --- |
| E10 | `79/100` | `157` | CoTracker + contact-part projection baseline |
| E11 | `79/100` | `157` | E10 已选 reference 上做 inpainting 后处理 |
| E12 | `79/100` | `156` | target-aware clean reference selection |

结论：

- E12 没有降低 subaction 覆盖率；
- final tuple 比 E10/E11 少 `1` 个；
- 数据量基本保持住了。

这说明 E12 没有靠“有手就全部丢弃”来换干净程度。

### 2. reference hand overlap 对比

| 指标 | E10 | E11 | E12 |
| --- | ---: | ---: | ---: |
| mean `reference_hand_overlap_ratio` | `0.151694` | `0.151694` | `0.121017` |
| median `reference_hand_overlap_ratio` | `0.141556` | `0.141556` | `0.102667` |

结论：

- E11 因为不改 reference selection，所以原始 reference hand overlap 和 E10 一样；
- E12 通过重新选帧，把 reference crop 级手重叠均值从 `0.151694` 降到 `0.121017`；
- 中位数也从 `0.141556` 降到 `0.102667`。

这说明 E12 从源头减少了 reference crop 里的手干扰。

### 3. object / contact part 遮挡对比

E11 追加了后处理遮挡指标，但由于它使用 E10 已选 reference，遮挡很重：

| 指标 | E11 | E12 |
| --- | ---: | ---: |
| mean `reference_object_hand_overlap_ratio` | `0.621823` | `0.176647` |
| mean `reference_contact_part_hand_overlap_ratio` | `0.691429` | `0.192162` |

结论：

- E11 中很多样本的手已经明显压住 object/contact part；
- E12 通过选帧把 object-hand overlap 和 contact-part overlap 大幅降下来；
- 这正好验证了 E12 的核心假设：严重遮挡时应该优先换帧，而不是强行 inpaint。

### 4. 投影质量对比

| 指标 | E10 | E12 |
| --- | ---: | ---: |
| mean `final_quality_score` | `0.983348` | `0.957274` |
| median `final_quality_score` | `1.000000` | `0.990714` |
| mean `affine_inlier_ratio` | `0.954086` | `0.896175` |
| median `affine_inlier_ratio` | `1.000000` | `0.971008` |
| mean `affine_median_residual` | `0.572806` | `0.830945` |
| median `affine_median_residual` | `0.428897` | `0.716215` |

结论：

- E12 的投影质量略低于 E10；
- 这是预期内的 trade-off，因为 E12 有时会选择更早但更 clean 的 reference；
- 但 E12 仍然保持了很高的 part gate 和 inside count：
  - final tuple 全部来自 `contact_part_local_affine`；
  - `part_gate_source = contact_part_mask`；
  - `whole_object_gate_fallback = 0`；
  - median `projected_contact_inside_count = 5`；
  - median `part_inside_count = 5`。

也就是说，E12 没有为了 clean selection 放弃投影正确性，只是接受了轻微的 projection quality 下降。

## 九、E12 是否达到了目标

E12 的目标不是单纯提高覆盖率，也不是继续把手硬擦掉，而是证明：

> 在 E10 投影准确的基础上，通过 target-aware reference selection，可以更优先选择“手尚未接触目标物体、目标物体仍可识别”的 reference frame，从源头减少训练图里的手部干扰。

从结果看，E12 基本达到了这个目标：

1. 覆盖率保持：
   - E10 `79/100`
   - E12 `79/100`

2. tuple 数基本保持：
   - E10 `157`
   - E12 `156`

3. CoTracker 仍然真实启用：
   - `cotracker = 365`
   - `fallback_lk = 0`

4. reference crop 手重叠下降：
   - mean 从 `0.151694` 降到 `0.121017`
   - median 从 `0.141556` 降到 `0.102667`

5. object/contact part 遮挡相比 E11 明显下降：
   - object-hand overlap mean 从 `0.621823` 降到 `0.176647`
   - contact-part hand overlap mean 从 `0.691429` 降到 `0.192162`

6. 投影精度基本维持：
   - part gate pass `365`
   - final tuple 全部为 `contact_part_local_affine`
   - no whole-object gate fallback
   - median projected contact inside count 为 `5`

但 E12 也暴露了一个现实限制：

> 在当前 HOA detection 和已有 reference 搜索窗口下，并不是每个样本都能找到 clean reference。

最终仍有 `71/156` 个 final tuple 被标为 `target_occluded_by_hand`。这说明 E12 比 E10/E11 更好地诊断和缓解了问题，但还没有完全解决 human-less reference 的问题。

## 十、下一步可能方向

E12 之后更合理的方向不是简单继续提高 clean score 权重，而是分层处理：

### 1. 对 clean class 做训练集过滤 / 加权

可以把 final tuple 分成：

- 高质量训练集：
  - `strict_target_handless`
  - `local_target_clean`
  - `hand_visible_target_not_occluded`
- 可选训练集：
  - `target_partially_occluded`
- 低优先级或只做分析：
  - `target_occluded_by_hand`

这样比 E10/E11 直接混在一起更可控。

### 2. 对 `target_occluded_by_hand` 再做轻量 inpaint

E12 不主张 inpainting 作为主方法，但可以在已经无法换帧时，把 inpaint 作为 fallback：

- `local_target_clean`：不需要 inpaint；
- `hand_visible_target_not_occluded`：可选轻量 inpaint；
- `target_partially_occluded`：谨慎 inpaint；
- `target_occluded_by_hand`：不建议直接作为高质量训练图。

### 3. 引入更好的 hand mask 或 object/part segmentation

当前 E12 的 hand mask 主要来自 hand bbox。bbox 会高估手区域，也会把部分物体算进手遮挡。后续如果有稳定 SAM2 / hand segmentation，可以把：

- `reference_object_hand_overlap_ratio`
- `reference_contact_part_hand_overlap_ratio`

算得更精确。

### 4. 针对 clean reference 扩展搜索策略

现在 E12 仍然受 E10 的 object track / reference window 约束。后续可以考虑在不放弃 object consistency 的前提下，给 clean reference 更多候选空间，而不是只在当前可跟踪窗口里排序。
