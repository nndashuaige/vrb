## 现在要解决的问题

当前目标不是只证明某一帧能跑通，而是把 VRB 的数据处理流程按 EPIC-KITCHENS 的 annotation subaction 对齐起来。理想状态是：每个 subaction 对应一批帧，这批帧尽量能跑完整个 pipeline，并生成可用于训练的数据处理结果。

每个可用样本至少应包含：

- contact points
- human-less reference frame
- homography 后的接触区域
- trajectory
- heatmap / overlay / 轨迹可视化
- 对应的 candidate_result.json 诊断信息

可以接受一定比例的 subaction 因为太短、遮挡、检测差、手/物体 bbox 缺失、homography 质量差等原因不可用。但如果大批 subaction 都跑不通，就需要定位瓶颈到底在 reference 选择、homography / geometry，还是 contact extraction。

### 今天进一步确认的问题

- 当前 reference 选择虽然已经带“最近的无手帧”约束，但还没有显式加入“同物体”约束。
- 现在 `find_strict_humanless_frame` 的职责仍然只是：
  - 在给定窗口中找最近的连续无手帧
  - 不判断 reference 上是否还是同一个被操作物体
  - 不对多个候选 reference 做质量排序
- 因此，当前 reference 选择的主要短板不是“完全没有约束”，而是“约束还不够语义化”：
  - 有最近性约束
  - 有无手约束
  - 但缺少物体一致性约束和 reference 质量排序

### 今天从 E2 / E3 对比中得到的新判断

- E2 失败但 E3 成功的很多样本，确实是被更长历史窗口“救活”的。
- 但被 E3 救活的这批样本，reference 往往离 contact 很远：
  - 对于 `E2 fail_reason == no_strict_humanless_frame` 且 `E3 status == keep` 的 110 个候选，

- 这说明：
  - “120 帧窗口偏窄”这个判断是成立的
  - 但 E3 的 full previous search 又明显过远，容易跨很长时间段，带来漂移和几何失真
- 这也解释了为什么 E3 的主失败原因会从 `no_strict_humanless_frame` 转成 `projected_object_polygon_invalid`

### 目前推测更合理的优化方向

- 不建议继续把 reference 策略理解成“固定窗口值调参”问题。
- 更合理的方向应是：把 reference 选择改成“受约束的自适应选择器”。

建议的主方案：

1. 保留“最近的 strict human-less frame”这个核心思想，不偏离论文语义。
2. 把搜索窗口改为分级回退，而不是单一固定值：
   - 先搜 `120`
   - 找不到再扩到 `240`
   - 再扩到 `360`
   - 默认不要直接走 full previous
3. 在 reference 候选选择里加入“同物体”约束：
   - reference 上应尽量还是同一个 active object
   - 可以跨 subaction，但不应跨物体
4. 如果一个窗口内有多个 human-less 候选，不应只按“最近”选，而应做简单打分：
   - 距离 contact 近
   - object continuity 更好
   - homography 预估质量更高
   - 遮挡更少

### 当前结论

- 当前 E2 不是无约束固定 reference，而是“有窗口约束的最近无手帧”。
- 现在最需要优化的，不是把 `120` 盲目改大，而是把 reference 逻辑从“单一时间窗口规则”升级为“最近性 + 无手 + 同物体 + 质量排序”的联合选择规则。

## 2026-5-11 今日发现

我认为你的直觉基本是对的，但要把“第一个动作”定义清楚。

不是“这个物体在整段视频里的第一个 verb”，而是：

**这个物体在一次新的接触 episode 里，接触后短时间内发生的第一个动作。**

也就是说，要区分三层东西：

1. `annotation row / subaction`
2. `object identity`，也就是 [EPIC_100_train.csv](/Users/huhu/Documents/Code/bishe/vrb/vrbreproduction/data/annotations/epic-kitchens-100-annotations/EPIC_100_train.csv) 里的 `noun` / `all_nouns`
3. `VRB training sample`

对 VRB 来说，真正的 sample 更像是：

- 有一个新的 contact 发生
- 在 contact 前能找到 human-less reference
- 只取 contact 后很短的一段 trajectory
- 不关心之后长时间拿着这个物体继续干什么

所以我不建议你做成“同一个 noun 只保留全局第一次动作”。那会太粗，也会丢掉很多本来有效的新接触样本。  
更合理的是：

**把 subaction 当候选，把 fresh contact episode 当最终筛选单位。**

推荐规则：

- 每条 annotation 先作为候选 subaction
- 用 `noun` / `all_nouns` 作为“这是哪个物体”的语义先验
- 只保留满足“这是一次新的接触开始”的 subaction
- 如果它只是前一个 subaction 的延续持握/延续操作，就跳过

“延续”可以这样定义：

- 和前一个 subaction 是同一 `noun`
- 时间上紧邻或重叠
- contact 前没有出现新的 no-hand gap
- 没有明显的 `0 -> 1` 新接触转变
- hand / object 关系看起来一直在持续

这样的话：

- `pick up potato -> peel potato`  
  如果 `peel potato` 发生时手早就在拿着 potato，而且没有新的无手 reference，那它更像 continuation，应该跳过。
- `put down potato -> pick up potato`  
  这是 release 后的新接触，应该保留。
- `open drawer`、`close drawer`  
  虽然 noun 一样，但如果是新的接触 episode，仍然可以是独立样本。

所以结论是：

**你不是按 annotation 直接全收，也不是按物体全局只取第一次。**
你应该做的是：

**“同物体 + 新接触 episode + 短期 post-contact”筛选。**

我建议下一步把策略定成这个版本：

- `annotation noun` 负责给出“目标物体是谁”
- `HOA contact transition + no-hand reference` 负责判断“是不是新的 episode”
- `VRB short trajectory` 负责保证“只学接触后的第一小段动作”

### 对 VRB 数据单位的当前判断

当前结果支持这个判断：

**VRB 数据生成不应该简单以“每个 subaction 中的 contact frame”为训练样本单位，而应该更接近“新的物体接触 episode + 短期 post-contact trajectory”。**

原因：

- 论文语义强调 first contact timestep 和 post-contact trajectory，而不是整个后续持物动作。
- E2 的 all-contact 策略能提高成功率，但会把很多同物体连续持握动作也当成候选。
- E4 显示，剔除 continuation 后，候选数大幅减少，但成功样本数只小幅下降。
- 因此 episode filtering 更接近论文中的“接触后短期动作”语义，也更适合作为后续数据生成主线。

但 E4 还不是最终方案。它只是一个基于 annotation noun 的弱语义 gate，目前还不能真正识别物体 instance，也不能判断 reference frame 上是否仍是同一个 object。下一步更合理的方向仍然是：

- episode gate：用 `noun/all_nouns + contact/no-hand gap` 判断是否为新接触 episode
- reference selector：用“最近性 + 无手 + 同物体 + homography 质量”联合打分
- trajectory：只保留 contact 后短期 hand trajectory，不扩展到整段后续动作

### 数据量是否足够训练新 VRB 的粗略估计

EPIC-KITCHENS 100 train annotation 当前共有 `67217` 条记录。

按这 100 个 subaction 的 E4 小样本通过率粗略外推：

- E4 成功样本数：`37 / 100 = 0.37` samples/subaction
- 外推到 67217 条 annotation：约 `67217 * 0.37 ≈ 24870` 个样本

论文 appendix 里 VRB 训练大约使用 `54K` image-trajectory-contact point tuples。按当前 E4 pipeline 的通过率，粗略外推只有约 `2.5 万` 样本，明显低于论文规模。

因此当前判断是：

- E4 的语义质量方向是对的，适合作为更干净的数据生成单位。

人工查看 E5 输出后发现，E5 虽然显著提高了样本数量，但存在明显的 label-quality 风险。

典型问题是 `open freezer` / `open drawer` / `close freezer` 这类样本：

- contact frame 上确实是手在接触冰箱门、抽屉或门；
- 但投影回 fallback reference frame 后，热力图区域可能落到地板、墙面或其他背景区域；
- 也就是说，最终 `label_heatmap_merged_overlay.png` / `vrb_style_affordance.png` 看起来是成功输出，但接触区域并不在真实被操作物体上。

这说明问题不在 heatmap 渲染本身。热力图只是把已经投影后的 contact means 可视化出来。真正的问题在更早的投影和 reference 语义：

1. **全局 homography 不适合可动关节物体**
   - 当前 homography 主要估计相机/背景运动；
   - 对 `freezer door`、`drawer`、`cupboard door` 这类会开合、旋转、平移的物体，物体本身不是静态背景平面；
   - 用背景 homography 把 contact points 投回去，会把门上的点错误地带到地板或背景上。

2. **当前 geometry gate 会出现“自洽但语义错误”**
   - 当前代码把 contact frame 的 active object bbox 也用同一个 H 投到 reference frame；
   - 然后检查 contact points 是否落在这个投影后的 bbox 附近；
   - 如果 homography 错了，contact points 和 object bbox 可能一起错位，因此仍然能通过 gate；
   - 但它们在 reference image 上并不对应真实物体位置。

3. **active object bbox 太粗**
   - 当前只用 2D bbox，不是精确 object mask；
   - 门、抽屉、冰箱这类结构的 bbox 很容易覆盖地板、边缘、背景；
   - 错误投影后更容易形成假阳性。

4. **E5 fallback 只保证 crop 干净，不保证物体语义一致**
   - `crop_level_humanless` 只检查 150x150 crop 是否少手或无手；
   - 它没有检查 reference frame 上该 crop 是否仍然覆盖同一个 object；
   - 因此它救回了很多样本，但也引入了语义不可靠的样本。

- E5 确实证明了 strict human-less 条件过严，会误杀不少 candidate；
- E5 也确实能显著提高小样本实验中的通过率；

- E5 成功数不能简单等价于高质量训练样本数。

更准确地说：

**E5 是一个 useful diagnostic experiment，而不是一个可以直接扩大规模的最终数据生成策略。**

今天继续检查 E5 输出后，确认了一个很关键的问题：

**E5 的表格指标变好了，但一部分可视化结果并不是真的对。**

最典型的现象是：

- 动作是 `open freezer`、`open drawer`、`close freezer`；
- contact frame 里，手确实接触的是冰箱门、抽屉或柜门；
- 但是投影回 fallback reference frame 后，热力图不在门/抽屉上，而是跑到了地板或背景上；
- 表格里这些样本可能显示 `keep`，但从训练数据角度看，这类样本是错 label。

也就是说，E5 的问题不是“有没有生成文件”，而是：

**生成出来的 label 有些不在真实目标物体上。**

### E5 为什么会出现这个问题

目前理解有几个原因。

第一，门、抽屉、冰箱门这类物体本身会动。

当前 pipeline 用 homography 把 contact point 从 contact frame 投回 reference frame。这个方法默认画面里的东西主要是静态的，只是相机在动。但门、抽屉、冰箱门不是静态背景，它们自己会开合、旋转、平移。

所以会出现这种情况：

- contact frame 里手接触的是冰箱门；
- 但 homography 更像是在对齐背景或地板；
- contact point 被当成背景平面上的点投回去；
- 最后点就可能落到地板上。

这不是 heatmap 本身画错了，而是 heatmap 使用的投影后 contact point 已经错了。

第二，当前 geometry gate 有一个“自己验证自己”的问题。

现在的逻辑大概是：

1. contact frame 里有 contact point；
2. contact frame 里也有 object bbox；
3. 把 contact point 投回 reference frame；
4. 也把 contact frame 的 object bbox 投回 reference frame；
5. 检查投回去以后，contact point 是否还在这个投影后的 object bbox 附近。

这个检查只能说明：

**点和框被同一个变换投回去以后，彼此还靠得比较近。**

但它没有说明：

**这个位置在 reference frame 上真的还是那个物体。**

如果 homography 错了，contact point 和 object bbox 可能一起被投到地板上。它们互相仍然靠近，所以当前 gate 可能放行。但真实图像里，地板上根本没有冰箱门。

这就是 E5 里最危险的假阳性。

第三，E5 fallback 只检查 crop 里有没有手，没有检查 crop 里是不是目标物体。

E5 的 `crop_level_humanless` 逻辑主要在问：

**这个 150x150 crop 里手是不是很少？**

但它没有继续问：

**这个 150x150 crop 里是不是还有我们要学的那个物体？**

所以如果投影点跑到地板上，地板区域通常也没有手，于是它会通过 crop hand overlap 检查。这个 crop 很“干净”，但它不是正确的训练图。

一句话总结：

**E5 把“无手且几何上看起来自洽”误当成了“无手且语义正确”。**

### 当前对四个原因的判断

之前总结过四类问题，现在更清楚了：

1. **物体会旋转/开合，2D homography 本身不一定能投对。**
   - 这个问题 E5b 不会真正修复；
   - E5b 只能识别出投影错了，然后把这种样本丢掉；
   - 不建议为了复现 VRB 直接改成 3D 坐标，因为论文本身用的是 2D pixel-space contact points 和 trajectory。

2. **当前 geometry gate 只做投影自洽检查，没有检查 reference frame 上真实物体。**
   - 这是 E5b 要重点解决的问题之一。

3. **object bbox 比较粗。**
   - 这会放大错误，但目前不认为它是最主要原因；
   - 暂时不优先上 segmentation 或 mask；
   - 先用 bbox 做弱一致性检查即可。

4. **E5 fallback 只保证 crop humanless，不保证物体对。**
   - 这是 E5b 要重点解决的另一个问题。

### 下一次实验：E5b

下一次实验建议做 E5b。

E5b 不要再继续放宽 reference，也不要改 heatmap，也不要改 3D。它只做一件核心事情：

**在 E5 fallback 的基础上，增加 reference frame 物体一致性检查。**

直观来说，E5b 要多问一句：

**投影回去以后，接触区域还真的在目标物体上吗？**

### E5b 具体要怎么检查

可以分两层检查。

第一层，保留当前的投影自洽检查：

- contact point 投回 reference frame；
- contact frame 的 active object bbox 也投回 reference frame；
- contact point 应该还在 projected object bbox 附近。

这层可以保留，但不能单独决定成功。

第二层，新增 reference frame 真实物体检查：

- 在 reference frame 上重新读取 object detections；
- 找 reference frame 里和 projected object bbox 最接近的 object bbox；
- 要求 projected object bbox 和 reference object bbox 有足够重叠；
- 或者要求 projected contact centroid 距离 reference object bbox 不要太远；
- 如果投影点落在地板上，而 reference frame 那里没有 object bbox，就丢掉。

换句话说：

- contact frame 的 object bbox 投回去，只能告诉我们“按 homography 推测，物体应该在这里”；
- reference frame 的 object bbox 告诉我们“图像里真实检测到的物体在这里”；
- 这两个东西必须对得上。

### E5b 主要解决什么问题

E5b 主要解决两个问题：

1. **解决 E5 fallback 只检查无手、不检查物体对不对的问题。**
   - 也就是解决“地板 crop 很干净，所以被误收”的问题。

### 当前问题判断

E4 / E5 / E5b 的结果说明，当前数据生成流程的问题不能只看“通过率”。E5 的数量接近论文 54K 量级，但人工查看发现部分 label 明显投到地板、背景或非目标物体上；E4 / E5b 数量不足，而且 strict 样本也不能证明完全没有 object consistency 风险。

目前怀疑的问题分两类：

1. **语义锚点问题**
   - 当前很多候选来自 subaction 内任意 contact frame，而不是一次 new contact 的起点。
   - reference 选择是相对 candidate frame 往前找，而不是相对 new contact start 往前找。
   - 这可能导致 reference 已经是物体被移动后的状态，不再符合论文里 initial / human-less image 的语义。

2. **几何投影问题**
   - 当前 homography 主要估计背景/相机运动，而不是被操作物体本身的运动。
   - 对 door / drawer / freezer / cupboard 这类 articulated object，物体自身会旋转、开合、平移，背景 homography 天然可能投歪。
   - 当前旧 geometry gate 有自证问题：contact point 和 active object bbox 用同一个 H 投回 reference 后仍然靠近，并不代表它们真的落在 reference frame 的真实目标物体上。

### 对四个核心问题的回答

#### 1. reference 强制来自当前 new contact 之前、且处于 pre-contact gap，投影是否明显更稳定？

部分更稳定，但不充分。

E6a-x 的成功样本 ref_gap 很短，语义上更接近论文中的 initial / human-less frame；一些样本热图确实更像落在目标物附近。

但仍有背景/地板/非目标风险，尤其是 door / cupboard / pan / cup 等样本。这说明 semantic anchor 修正只能减少一类错误，不能替代 object consistency 或更强的 projection 检查。

#### 2. E5 / E5b 的坏样本是否主要来自 candidate 太晚，或者 reference 已经不是物体移动前状态？

不能只这样解释。

E6a-x 已经把 candidate 限制在 `t0..t0+2`，reference 也限制在 `t0` 前 pre-contact gap，但仍有投影质量问题。坏样本至少还有一部分来自 homography / object motion / reference-frame true object mismatch。

#### 3. 固定 120 帧窗口是否本身就是错误语义？

是。

固定 120 帧窗口把 reference 搜索定义成了一个工程范围，而不是当前 contact episode 的语义前状态。E6a-x 改成 pre-contact gap 后，很多旧候选直接变成 `no_pre_episode_reference_window`，说明旧窗口确实可能纳入语义上不属于当前 episode 的 reference。

但固定 120 不是唯一问题。即使窗口语义修正，projection 仍然需要额外质量控制。

#### 4. new contact episode 作为样本单位后，tuple 数量和质量分别怎么变化？

数量下降，语义更干净，但质量没有自动变成可靠。

- tuple 数量：E6a-x 成功 `25`，低于 E4 的 `37` 和 E5b 的 `41`。
- episode 数量：前 100 个 subaction 中有 `293` 个 new-contact episodes，说明一个 subaction 内确实经常有多个 new contact episodes。
- 质量：reference / candidate 语义更明确，但仍需要 object-level 检查和人工 projection audit。

### E6b / E6c / E6d 是否需要调整实验方案

结论：需要调整，但不应该推翻原来的分层 ablation 结构。

必须保留的共同基线：

- 数据单位继续是 `new contact episode`。
- candidate 继续只取 `t0`, `t0+1`, `t0+2`。
- reference 搜索继续锚定 `t0`。
- semantic window 继续是当前 episode 前的 `pre-contact gap`。
- `MAX_REF_BACKTRACK` 继续只作为工程保护。
- 不允许 full previous reference。
- 不回退到旧版固定 `[t0-120, t0-1]` 语义。

需要调整的是 E6b / E6c / E6d 的具体诊断目标和 hard reject 范围。

### E6b 调整建议

原计划：

- `E6b = E6a-x + crop-level humanless fallback`

这个方向仍然需要做，但要收窄解释范围。

E6b 不应该尝试救 `no_pre_episode_reference_window`。如果当前 episode 前没有 pre-contact gap，那么 reference 语义窗口为空，crop-level fallback 也没有语义基础。强行 fallback 会重新引入 E5 的问题：reference 可能不是当前物体移动前状态。

E6b 应该只救这类候选：

- 有非空 pre-contact gap。
- `effective_reference_window_start_0_based <= effective_reference_window_end_0_based`。
- strict global no-hand 找不到，即 `no_strict_humanless_frame`。
- fallback reference 仍必须来自 E6a-x 的 effective pre-contact window。

E6b 需要新增/强调这些统计：

- `pre_contact_window_nonempty`
- `strict_unavailable_but_gap_nonempty`
- `crop_fallback_attempted_only_when_gap_nonempty`
- `fallback_reference_in_pre_contact_gap`
- `fallback_ref_before_episode_start`
- `fallback_rescued_from_no_strict_humanless`
- `no_pre_episode_reference_window_not_rescued`

E6b 的成功标准不能只看数量提升。必须单独报告：

- strict success count。
- fallback success count。
- fallback 的 `ref_gap / reference_anchor_gap / gap_length_before_episode_start`。
- fallback 成功样本的人工质量，尤其是否重新出现地板/背景热图。

E6b 的预期：

- 成功数可能从 E6a-x 的 `25` 提升，但理论上不可能救回 `no_pre_episode_reference_window=283` 这一大块。
- 如果提升很小，说明 strict global no-hand 不是 E6a-x 后的唯一瓶颈。
- 如果提升很大但人工质量差，说明 crop fallback 仍高风险。

### E6c 调整建议

原计划：

- `E6c = E6b + reference-frame object consistency`
- 主要控制 fallback 假阳性。

E6a-x 之后，这个方案需要加强：object consistency 不应该只检查 fallback，也应该检查 strict 样本。

原因：

- E6a-x 没有任何 crop fallback，全部是 strict reference。
- 但 strict 成功样本里仍观察到背景/地板/非目标风险。
- 这说明 strict global no-hand 并不等价于 reference-frame object consistency。

建议 E6c 分成两个统计层：

1. object consistency record-only 层
   - 对所有 strict 和 fallback 样本都记录 reference-frame object consistency 诊断。
   - 字段继续包括：
     - `reference_object_consistency_pass`
     - `reference_object_consistency_reason`
     - `reference_object_bbox`
     - `reference_object_iou`
     - `reference_object_center_distance`
     - `projected_contact_to_reference_object_distance`
     - `projected_contact_means_inside_reference_object_count`
     - `reference_object_candidate_count`

2. hard reject 层
   - 第一版建议至少对 fallback hard reject。
   - 同时额外输出一个 strict-hard-reject shadow metric：不一定马上丢 strict 样本，但要统计“如果 strict 也 hard reject，会剩多少”。

更推荐的 E6c 设计：

- 主结果：fallback hard reject，strict 记录诊断。
- 附加结果：`E6c_strict_object_consistency_shadow`，报告 strict 样本中 object consistency fail 的比例。

这样可以避免一次性把 strict 样本杀太多，同时回答 E6a-x 暴露的新问题：strict reference 也可能投到背景。

E6c 的核心问题应改成：

- object consistency 能否解释 E6a-x strict 样本中的背景/非目标风险？
- fallback 新增样本有多少能通过真实 reference object 检查？
- object detection 缺失导致的误杀比例有多高？

### E6d 调整建议

原计划：

- `E6d = E6c + articulated object strict policy`

这个方向仍然需要，但不要只把 E6d 理解成 fallback 的补丁。E6a-x 结果显示，即使 strict + pre-contact gap，door / cupboard 等 articulated object 仍有风险。

- `cupboard`

- 因此 E6b 的数量提升不等于质量合格。crop-level humanless 能放宽 strict no-hand，但不能解决 object consistency 或 articulated / deformable / hand-action 场景的投影假阳性。

### 结论

E6b 回答了本轮核心问题：strict global no-hand 的确是 E6a-x 后的一个独立瓶颈。只在 pre-contact gap 内做 crop-level fallback，可以把最终成功样本从 `25` 提升到 `74`，且没有越过 `no_pre_episode_reference_window` 语义边界。

但 E6b 也证明：只靠 crop-level humanless fallback 会重新放大背景/非目标风险。尤其当 reference crop 没有手，不代表 projected contact 一定对齐 reference frame 的真实目标物。

下一步如果继续做 E6c，应重点做：

- 对 strict 和 fallback 都记录 reference-frame object consistency。
- 对 fallback hard reject object consistency fail。
- strict 样本先做 shadow hard reject 统计。
- 对长 ref_gap fallback 样本单独标记风险。

当前不建议把 E6b 全部 fallback 成功样本直接作为训练数据；更适合作为 E6c object consistency 的输入集合。

## 2026-5-18 今日记录：E6c 目的与方案修订

### 为什么需要调整 E6c

E6b 已经说明：crop-level humanless fallback 可以显著提升数量，但 fallback 成功样本里仍有明显背景/非目标风险。因此 E6c 仍然要做 `E6b + reference-frame object consistency`，但不能只做一个简单的 pass/fail hard reject。

原因是 HOA reference frame object bbox 本身可能缺失或不稳定。`no_reference_object_bbox` 这类情况说明检测器没有提供证据，不等价于投影一定错误。如果把所有 object consistency fail 都直接当成真实 mismatch，E6c 会混淆两类问题：

1. projected object / contact 明确和 reference frame 真实 object bbox 不一致。
2. reference frame 上没有可用 object bbox，object consistency 无法评估。

所以 E6c 应改成质量诊断实验，而不是单一追数量或单一 hard reject pipeline。

### E6c 更新后的目标

E6c 的目标是：

- 在 E6b 的 74 个成功样本基础上，判断哪些样本有 reference-frame object-level 证据支持。
- 重点评估 E6b 新增的 49 个 fallback 成功样本。
- 同时对 E6b 的 25 个 strict 成功样本做 object consistency record-only / shadow reject，因为 strict global no-hand 也不能保证 object-level correctness。
- 区分 definite mismatch 和 detector unknown，避免把检测器缺失误当作投影错误。

E6c 不以成功数最大为目标。更重要的是回答：object consistency 是否真的能筛掉 E6b 中的背景/非目标热图风险。

### E6c 保持不变的基础约束

E6c 必须继承 E6b / E6a-x 的语义定义：

- 数据单位仍是 `new contact episode`。
- candidate 仍只取 `t0`, `t0+1`, `t0+2`。
- reference 搜索仍锚定 `t0`。
- raw semantic window 仍是 `[pre_contact_gap_start, t0 - 1]`。
- effective window 仍是 `[max(pre_contact_gap_start, t0 - MAX_REF_BACKTRACK), t0 - 1]`。
- `MAX_REF_BACKTRACK` 只是工程保护，不是语义定义。
- crop fallback 仍只能在 strict global no-hand 找不到、且 effective pre-contact window 非空时尝试。
- 不允许 full previous reference。
- 不允许回退旧版固定 `[t0-120, t0-1]`。
- 不救 `no_pre_episode_reference_window`。
- 不做 articulated object special policy；这留给 E6d。
- 不改 contact extraction / GMM / homography / heatmap 主逻辑。

### E6c object consistency 状态分类

E6c 不应只有二分类 pass/fail。建议新增：

- `reference_object_consistency_status`
  - `pass`
  - `fail_definite_mismatch`
  - `unknown_no_reference_object_bbox`
  - `unknown_missing_projected_object`
  - `unknown_invalid_geometry`
- `reference_object_consistency_evaluable`
- `reference_object_consistency_pass`
- `reference_object_consistency_reason`

分类原则：

- 如果 reference object bbox 存在，且 IoU / contact-near-bbox / center distance 等条件满足：`pass`。
- 如果 reference object bbox 存在，但 projected object/contact 明确不匹配：`fail_definite_mismatch`。
- 如果 reference frame 没有 object bbox：`unknown_no_reference_object_bbox`。
- 如果 projected object bbox 缺失或无效：`unknown_missing_projected_object`。
- 如果几何结果不足以评估：`unknown_invalid_geometry`。

### E6c 两套统计口径

E6c summary 必须同时报告两套口径。

#### 1. conservative / training-safe 口径

用于判断“如果要作为训练候选，最保守应该剩多少”。

规则：

- fallback 样本只有 object consistency `pass` 才进入 final conservative set。
- fallback 的 `fail_definite_mismatch` 和所有 `unknown_*` 都不进入 conservative final set。
- strict 样本第一版仍不 hard reject，但要报告 strict conservative shadow count。

这个口径更适合训练数据选择。

#### 2. diagnostic / evaluable-only 口径

用于判断 object consistency gate 本身是否有效。

规则：

- fallback 样本中：
  - `pass` 记为可支持。
  - `fail_definite_mismatch` 记为明确应丢。
  - `unknown_*` 单独列出，不混进 pass，也不混进 definite fail。
- strict 样本同样按 pass / definite mismatch / unknown 三类统计。

这个口径更适合分析检测器缺失和真实投影错误各占多少。

### E6c hard reject 策略更新

第一版 E6c 建议：

- fallback conservative final：只保留 object consistency pass。
- fallback definite mismatch：hard reject。
- fallback unknown：不进入 conservative final，但不要算作 definite mismatch；单独导出。
- strict：不实际 hard reject，只 record-only；但必须输出 strict shadow reject 和 strict unknown 统计。

也就是说，E6c 输出里要同时能回答：

- 如果训练要保守，E6b 的 49 个 fallback 成功剩多少？
- 如果只看可评估样本，object consistency 筛掉多少明确 mismatch？
- 有多少样本是因为 reference object bbox 缺失而无法判断？
- strict 的 25 个成功样本里有多少也存在 object-level 风险？

### E6c summary 必须强调

E6c 不是为了超过 E6b 的 74 个样本。合理结果很可能是：

- conservative final count 小于 E6b。
- fallback count 明显下降。
- unknown 样本占一定比例。

这不是失败。真正的判断标准是：

- object consistency 是否能筛掉 fallback contact sheet 中明显背景/非目标样本。
- unknown 是否主要来自 reference object bbox 缺失。
- strict 样本是否也暴露出 object-level mismatch 风险。

### E6 这一批实验验证了什么

这说明 E6 这批实验在时间语义上是正确的：确实更像是在学习“新接触发生前的初始画面”，而不是动作已经发生后的状态。

但是这只说明“参考帧时间选对了”，不说明“投影一定落在真实目标物上”。

### Projection（投影）和 object consistency（物体一致性）问题

E6c 的结果说明，现在最大的质量问题不是简单的 homography（单应性矩阵，用来把后续帧点位投回参考帧）有没有算出来。

更准确地说：

- 很多样本能算出 homography（单应性矩阵），也能通过 geometry gate（几何自洽检查）。
- 但 geometry gate（几何自洽检查）主要验证“投影后的接触点和投影后的目标框彼此靠近”，它不等于验证“它们真的落在参考帧里的真实目标物上”。
- E6c 的 object consistency（物体一致性检查）才是在问：参考帧里真实检测到的目标物框，是否和投影结果对得上。

E6c definite fail（明确失败）样本里能看到明显的地板、水槽边、背景、非目标物风险，说明 object consistency（物体一致性检查）确实有价值。

但 unknown_no_reference_object_bbox（未知：参考帧没有检测到目标物框）太多，说明当前检测器覆盖率不足。也就是说，现在很多样本不是“确认投错”，而是“缺少判断证据”。

### Articulated object（可开合物体）单独判断

这里的 articulated object（可开合物体）主要包括：

- door（门）
- drawer（抽屉）
- freezer（冷冻柜）
- cupboard（橱柜）
- cabinet（柜子）
- fridge / refrigerator（冰箱）

E6b 把不少 articulated object（可开合物体）样本重新带了回来，尤其是：

- put beer into drawer（把啤酒放进抽屉）
- open drawer（打开抽屉）
- close cupboard（关闭橱柜）
- open cupboard（打开橱柜）
- close freezer（关闭冷冻柜）
- close door（关门）

这些样本有两类风险：

1. 物体本身会运动，例如门、抽屉、柜门会旋转、平移或开合；background homography（背景单应性矩阵）不一定适合描述目标物自身运动。
2. 很多 reference object bbox（参考帧目标物框）缺失，导致 E6c 无法判断到底是投影错，还是检测器没检测出来。

所以当前不应该把 articulated object（可开合物体）直接混进普通训练集。更合理的是先单独隔离，做人工 audit（人工审核）和 E6d-lite（轻量版第 6 组 d 诊断）。

### 为什么现在不继续做完整 E6d

E6d（第 6 组 d）原本是在 E6c（第 6 组 c）基础上继续对 articulated object（可开合物体）收紧。

但 E6c 已经显示，当前主要瓶颈不是“规则不够严”，而是 reference object bbox（参考帧目标物框）大量缺失。

如果现在直接做完整 E6d（第 6 组 d），很可能只是进一步减少样本，却仍然不能回答关键问题：

- 是目标物真的投歪了？
- 还是参考帧里目标物检测器没给框？
- 是 articulated object（可开合物体）本身运动导致 background homography（背景单应性矩阵）不适用？
- 还是 detector unknown（检测器无法判断）太多？

因此现在不建议继续完整 E6d 主实验。

更合理的下一步是：

1. 先人工 audit（人工审核）E6c 的 pass（通过）、fail_definite_mismatch（明确不匹配）、unknown_no_reference_object_bbox（未知：参考帧没有目标物框）三类 contact sheet（接触热图拼图）。
2. 做 E6d-lite（轻量版第 6 组 d 诊断）：不重跑完整 pipeline（流程），只基于现有 E6b / E6c 输出分析 articulated object（可开合物体）。
3. 优先分析和改善 reference object bbox（参考帧目标物框）的检测与跟踪。

### 最终回答六个问题

1. 当前最大问题到底是 reference anchor（参考帧锚点）语义错，还是 homography（单应性矩阵）算法本身不够？

旧流程里 reference anchor（参考帧锚点）确实错得明显，E6a-x 已经验证了这一点。但修正以后，当前剩余最大问题更像是 object-level correctness（目标物层面的正确性）不足，也就是投影结果是否真的落在参考帧里的真实目标物上。

2. 在 new-contact anchor（新接触锚点）后，strict reference（严格参考帧）的样本质量是否明显提高？

时间语义明显提高了，参考帧更接近动作前状态。但 strict reference（严格参考帧）仍不能保证目标物层面正确，E6c 的 strict shadow（严格样本影子统计）里仍有明确不匹配和大量未知。

3. crop-level fallback（局部无手补救）在正确 anchor（锚点）下是否仍然可用？

可用，但只能当候选恢复器，不能当最终质量保证。E6b 证明它能救数量，E6c 证明它必须再经过 object consistency（物体一致性检查）和人工审核。

4. object consistency（物体一致性检查）是有效质量门控，还是主要受 reference object detection（参考帧目标物检测）缺失限制？

两者都是。它能筛掉一批明显坏样本，但当前主要受 reference object bbox（参考帧目标物框）缺失限制，导致大量 unknown（未知）。

5. articulated object（可开合物体）是否应该暂时禁用、单独收紧，或未来单独设计 projection / tracking（投影 / 跟踪）方案？

现在应单独隔离和收紧，不建议直接混入主训练集。未来最好单独设计 projection / tracking（投影 / 跟踪）方案，尤其是门、抽屉、柜子、冰箱这类自身会运动的物体。

6. 哪个实验最适合作为下一轮大规模生成 baseline（基线方案）？

E6b（第 6 组 b）最适合作为候选生成 baseline（基线方案），因为它在不越过接触前语义边界的前提下恢复了数量。但最终训练数据不能直接用 E6b 全量结果，必须接 E6c（第 6 组 c）的质量诊断和人工审核。

### 下一步建议

当前建议不要继续完整 E6d（第 6 组 d）主实验。

下一步优先级：

1. 人工审核 E6c 的三类图：pass（通过）、fail_definite_mismatch（明确不匹配）、unknown_no_reference_object_bbox（未知：参考帧没有目标物框）。
2. 做 E6d-lite（轻量版第 6 组 d 诊断），专门统计 door（门）、drawer（抽屉）、freezer（冷冻柜）、cupboard（橱柜）、cabinet（柜子）、fridge / refrigerator（冰箱）。
3. 改善 reference object bbox（参考帧目标物框）的检测和跟踪。
4. 如果要准备下一轮大规模生成，使用 E6b（第 6 组 b）作为候选生成基础，再用 E6c（第 6 组 c）和人工审核做质量控制。
