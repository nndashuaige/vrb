# e20 2026-7-7

## 一、E20 实验设计思路

E20 是在 E18B 之后做的"两遍式 hand inpaint + 标签重绘"实验。

E18B 已经把前 100 个 subaction 的 paper-faithful 成功样本提高到 56 个，但 reference 帧里仍然可能有手：

- `active_hand_invisible_pre_contact` 只保证 active hand 不可见，不保证另一只手或漏标手不可见；
- `min_hand_object_iou_pre_contact_fallback` 本来就允许手还在画面里，只要求 hand-object IoU 最小；
- E18B 的 `label_heatmap_merged_overlay.png` 和 `vrb_style_affordance.png` 是画在原 reference 图上的成品，如果直接后处理擦手，会破坏标签像素。

因此 E20 的核心目标是：

> 先按 E18B 口径导出 56 个 keep 和标签几何参数；GPU/worker 只负责 inpaint；最后用缓存的几何参数把 heatmap、轨迹、接触点重绘到 inpaint 后底图上。

这个设计来自 E19 的结论："先算几何，后换底图重绘"比直接在成品图上擦手更可控。

## 二、E20 和 E18B / E19 的关系

E20 沿用 E18B 的 candidate/reference/geometry 口径，只新增 hand inpaint 相关阶段：

```text
export   本地：重放 E18B 逻辑，导出 labels.json、reference_frame.png、hand bbox
pack     本地：打包 gpu_job
gpu      服务器/worker：生成 mask 和 inpaint 候选
ingest   本地：读取 gpu 结果，按 QC 选择 final
finalize 本地：同函数同参数，把标签重绘到 final reference 上
report   本地：生成 manifest、quality、contact sheet、summary
```

## 三、运行口径

E20 这一版实际跑的是严格 QC 基线，不是最终的 SU 同款 GPU 版本。

GPU/worker 摘要显示：

```text
device: cpu
backends: telea
started_utc: 2026-07-07T10:11:36Z
finished_utc: 2026-07-07T10:11:38Z
```

也就是说 E20 更像是验证全链路 plumbing 的 baseline：

- mask/inpaint/finalize/report 能否跑通；
- mask 外像素检查是否能守住；
- 标签重绘是否能做到 `selfcheck=0`；
- 严格 QC 下会有多少样本被保留为真正 inpaint final。

## 六、和 E18B manifest 的一致性

E20 export 输出 56 行，但 `consistency_report.json` 里 `keep_set_match=false`。

差异不是 GPU/inpaint 阶段造成的，而是 export 对照历史 manifest 时发现的一个样本级不一致：

| 只在 E20 export 中 | 只在 E18B manifest 中 |
| --- | --- |
| subaction 32, ref_idx 2941, `active_hand_invisible_pre_contact` | subaction 74, ref_idx 12167, `min_hand_object_iou_pre_contact_fallback` |

这个问题在 E20-A 也同样存在，属于 E18B 历史 manifest / 当前重放口径之间的已知差异。E20 后续分析以本次 export 自产的 56 行为准。

## 七、结论

1. E20 成功验证了两遍式架构：先缓存 labels 几何参数，再换 inpaint 底图重绘；最终 56 个样本的重绘自检全部为 0。
2. 严格 QC 口径非常保守：56 个样本里只有 1 个被接受为 final inpaint，其余 55 个保留原图。
3. 这一版没有真正实现 Seeing-the-Unseen 同款 GPU 质量增强流程，更适合作为 plumbing / strict-QC baseline。
4. 如果目标是"拿到 SU 同款候选图"，需要像 E20-A 那样使用 SAM ViT-H + LaMa + SD inpainting + SDEdit，并在 manifest 中显式区分 `qc_passed_final` 与 `prefer_generated` 产物。

## 八、遗留问题

- 严格肤色比例 QC 对厨房/手臂场景过于敏感，很多视觉上已经生成候选图的样本仍被判 fail；
- E18B 历史 manifest 与当前 export 有 1 个样本差异，后续若要做论文级复现实验，需要单独锁定数据版本和 candidate cache；
- E20 的输出证明重绘机制可用，但不能作为最终"无手训练图"质量结论。
