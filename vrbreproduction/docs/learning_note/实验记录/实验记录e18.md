# e18 2026-6-18

## 一、E18 实验设计思路

E18 是在 E16 / E17 之后做的一个 hybrid reference 实验。

E16 证明了：

> 把 reference 从 strict global no-hand 放宽到 active-hand-invisible 后，结果能从 E15 的 `14/100` 提升到 `26/100`。

但 E16 的问题也很明显：

- 找不到 active-hand-invisible reference 时，样本直接失败；
- 这些失败里，有些并不是真的没有 pre-contact reference，而是 active hand 一直在画面里；
- 如果手还在画面里，但手和物体还没有接触，理论上也可以作为 reference。

E17 则走了另一个方向：

> 不再要求 active hand invisible，直接使用 contact 前 `5-10` 帧内最近可用帧。

E17 的结果很好，`subactions_success = 47/100`，但它的问题是 reference 选择过于诊断化：

- `5-10` 帧 offset 是人工设定；
- 没有真正判断“手和物体是否没接触”；
- 更像 near-contact diagnostic baseline，而不是更稳定的语义规则。

因此 E18 的核心目标是：

> 保留 E16 的 strict-first 思路；如果 E16 找不到 active-hand-invisible reference，再用自动策略 fallback，选择 hand-object IoU 最小的 pre-contact frame。

也就是说：

```text
先找 active hand 不可见的帧；
找不到时，再找手和物体重叠最小的帧。
```

E18 希望回答的问题是：

1. E16 找不到 active-hand-invisible reference 的样本，是否可以被 hand-object IoU fallback 救回？
2. fallback 是否能保留比 E16 更多的 final tuple？
3. 和 E17 的 near-contact offset 相比，E18 是否能用更有语义的策略达到接近的效果？

## 二、E18 是在哪份代码上改的

```text
src/vrbreproduction/e18_hybrid_min_iou_reference.py
```

它是以 E16 的主体结构为基础，并吸收 E17 的“reference 不能过严”这个诊断结论后实现的。

主要基底来自：

```text

```

保留 E16 的主体结构：

- `video_id = P01_109`
- 前 `100` 个 EPIC annotations
- 一个 subaction 最多输出一个 final tuple
- 每个 subaction 只取第一个 new contact run
- candidate frame 固定为该 run 的 start frame，也就是 `t0`
- 不尝试 `t0+1/t0+2`
- Cell2 contact extraction / GMM 不改
- Cell3 homography + geometry gate 不改
- Cell4 heatmap generation 不改
- trajectory 逻辑不改


## 三、E18 改了什么

E18 的核心改动只在 reference selection。

### 1. 保留 E16 的主 reference

第一优先级仍然是 E16 的规则：

```text
active_hand_invisible_pre_contact
```

也就是：

> 在 episode start 之前，找最近的 active hand 不可见帧。

E18 当前版本已经把 `max_ref_backtrack` 改回和 E16 一致：

```text
max_ref_backtrack = 360
```

所以 reference 搜索窗口为：

```text
episode_start - 360  到  episode_start - 1
```

这意味着 E18 和 E16 一样，允许 reference 往前跨出当前 subaction，只要还在最多 360 帧回看窗口内。

### 2. 新增 min-IoU fallback

如果找不到 active-hand-invisible reference，E18 不再直接失败，而是进入 fallback。

fallback 的候选帧仍然来自同一个 pre-contact backtrack window：

```text
episode_start - 360  到  episode_start - 1
```

对每个候选 reference frame：

1. 读取 active hand bbox；
2. 读取 object bboxes；
3. 选择和 active hand 最相关的 active object bbox；
4. 计算 hand-object IoU；
5. 选择 IoU 最小的那一帧。

fallback reference mode 为：

```text
min_hand_object_iou_pre_contact_fallback
```

如果多个帧 IoU 一样，则按以下顺序排序：

1. `hand_object_iou` 越小越好；
2. `active_contact_binary == 0` 优先；
3. `any_contact_binary == 0` 优先；
4. 距离 episode start 更近优先；
5. object bbox score 更高优先。

直观理解：

> 如果没有“active hand 不在画面里”的 reference，就找“手还在，但手和物体最不像接触”的 reference。

### 3. 新增 diagnostics 字段

E18 在 `candidate_diagnostics.csv` 里新增/启用了以下 fallback 诊断字段：

```text
fallback_reference_used
fallback_reference_attempted
fallback_candidate_count
fallback_selected_rank_reason
fallback_selected_object_score
fallback_selected_distance_to_episode_start
fallback_selected_active_contact_binary
fallback_selected_any_contact_binary
fallback_selected_hand_missing
reference_hand_object_iou
reference_hand_object_center_distance
reference_object_bbox
reference_object_bbox_score
reference_object_candidate_count
```

这些字段用于回答：

- fallback 有没有被触发；
- fallback 一共看了多少个候选帧；
- 最终选中的 reference hand-object IoU 是多少；
- fallback 选中帧离 episode start 多远；
- fallback 是否真的选到了 contact binary 为 0 的帧。

## 四、E18 和 E16 / E17 的核心差异

| 项目 | E16 | E17 | E18 |
| --- | --- | --- | --- |
| 主 reference | active hand invisible | near-contact pre-frame | active hand invisible |
| fallback | 无 | 无 | min hand-object IoU |
| reference 搜索窗口 | episode 前最多 360 帧 | `t0-5` 到 `t0-10` | episode 前最多 360 帧 |
| 是否要求 active hand 不可见 | 是 | 否 | 主策略要求；fallback 不要求 |
| fallback 判断依据 | 无 | 无 | hand-object IoU 最小 |
| 是否手工 offset | 否 | 是，`5-10` | 否 |
| 语义定位 | paper-faithful active-hand-invisible | near-contact diagnostic | hybrid semantic fallback |

E18 和 E16 的区别：

```text
E16 找不到 active-hand-invisible reference 就失败；
E18 找不到 active-hand-invisible reference 时，会继续找 hand-object IoU 最小的 pre-contact frame。
```

E18 和 E17 的区别：

```text
E17 直接用 contact 前 5-10 帧；
E18 不使用手工 5-10 帧，而是在 E16 的 360 帧搜索窗口里自动选择 IoU 最小帧。
```

## 六、E18 和 E16 / E17 对比

| experiment | subactions_success | heatmap_pass | ref_found | strict_ref_found | active_hand_invisible_ref_found | fallback_ref_found | homography_available | geometry_pass | median anchor gap |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| E16 | 26 | 26 | 38 | 27 | 38 | 0 | 29 | 26 | 13 |
| E17 | 47 | 47 | 81 | 5 | 20 | 0 | 52 | 47 | 5 |
| E18 | 45 | 45 | 58 | 27 | 38 | 20 | 49 | 45 | 14 |

几个关键观察：

### 1. E18 明显超过 E16

E16：

```text
subactions_success = 26
```

E18：

```text
subactions_success = 45
```

提升来自 fallback：

```text
fallback_ref_found = 20
fallback_ref_keep = 19
```

也就是说，E18 中几乎所有找到 fallback reference 的样本都通过了最终 heatmap gate。

### 2. E18 接近 E17，但语义更强

E17：

```text
subactions_success = 47
```

E18：

```text
subactions_success = 45
```

E17 仍略高 2 个，但 E17 的 reference 是手工 near-contact offset：

```text
t0-5 到 t0-10
```

E18 则使用更自动、更可解释的 fallback：

```text
在 pre-contact window 里选 hand-object IoU 最小帧。
```

因此 E18 比 E17 更适合作为语义上可解释的改进方案。

### 3. E18 保留了 E16 的 active-hand-invisible 成功样本

之前有一个中间版本曾经把 reference 限制在当前 subaction 内，导致 active-hand-invisible keep 只剩 14。

最终版本已改回 E16 的 `max_ref_backtrack = 360` 逻辑后：

```text
active_hand_invisible_pre_contact keep = 26
```

这和 E16 的 final keep 数一致。

## 七、E18 的真实漏斗

E18 的主漏斗是：

| 阶段 | 剩余 | 本层损失 |
| --- | ---: | ---: |
| 100 subactions | 100 | - |
| 有 new-contact episode | 81 | 19 |
| Cell2 contact/GMM pass | 58 | 23 |
| reference found | 58 | 0 |
| homography available | 49 | 9 |
| geometry pass | 45 | 4 |
| final heatmap pass | 45 | 0 |

这里最重要的结论是：

> E18 已经基本解决了 E16 的 reference 找不到问题；当前更大的瓶颈回到了 Cell2 和 homography/geometry。

### 1. Cell2 损失 23 个

81 个 new-contact candidate 里，只有 58 个通过 Cell2。

Cell2 失败原因主要是：

| fail_reason | 数量 |
| --- | ---: |
| missing_hand_or_object_bbox | 11 |
| contact_points_lt5_after_object_boundary_filter | 11 |
| gmm_failed:ValueError | 1 |

这 23 个失败发生在 reference selection 之前。

也就是说：

```text
它们和 E18 的 active-hand-invisible / fallback reference 无关；
它们是在 contact frame 上就无法生成有效 contact tuple。
```

当前 Cell2 只看 episode start，也就是 `t0` 这一帧。

因此后续 E19a 的自然方向是：

> 如果 `t0` 这帧 Cell2 失败，就在同一个 new-contact episode 内尝试 `t0+1` 到 `t0+5`，看看附近帧是否有更稳定的 hand/object bbox 和 contact points。

### 2. Reference found 不再掉样本

E18 中：

```text
cell2_pass = 58
ref_found = 58
```

说明只要 Cell2 能过，E18 总能找到 reference：

- 38 个使用 active-hand-invisible；
- 20 个使用 min-IoU fallback。

这说明 E18 的 reference fallback 很有效。

### 3. Homography / geometry 仍有少量损失

```text
ref_found = 58
homography_available = 49
geometry_pass = 45
heatmap_pass = 45
```

reference 找到后，主要还会损失：

- 9 个 homography 失败；
- 4 个 geometry 失败；
- Cell4 heatmap 没有额外损失。

## 八、E18 的意义

E18 的主要结论是：

> 在 E16 的 active-hand-invisible 规则之外，加入 hand-object IoU 最小帧 fallback，可以显著提升最终可用样本数。

更具体地说：

1. E18 保留了 E16 的语义主线；
2. E18 不像 E17 那样使用手工 `5-10` 帧 offset；
3. E18 fallback 依据是视觉检测量：hand-object IoU；
4. E18 从 E16 的 `26/100` 提升到 `45/100`；
5. E18 和 E17 的 `47/100` 已经非常接近。

因此 E18 是一个比 E17 更可解释的 reference 改进版本。

---

## 九、当前问题和下一步

E18 虽然明显提升，但仍没有超过 E17。

当前主要瓶颈不是 reference，而是：

```text
Cell2 contact frame 只看 t0 一帧。
```

这会导致一些 subaction 因为 `t0` 上 hand/object bbox 漏检或 contact points 太少而被筛掉。

下一步建议做 E19a：

```text
保持 E18 reference 策略不变；
如果 t0 的 Cell2 失败，则在同一个 new-contact episode 内尝试 t0+1 到 t0+5；
选择第一个 Cell2 成功的 contact frame 继续跑 Cell3/Cell4。
```

E19a 要回答的问题是：

> 81 -> 58 这一步 Cell2 损失的 23 个样本，有多少可以通过同一 episode 内的相邻帧救回？
