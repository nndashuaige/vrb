# e9 2026-5-20

## 一、E9 实验方案

E9 的核心目标，是在不回到 background homography（背景单应性）、不简单放宽 gate threshold（门控阈值）、也不把 object trajectory（物体轨迹）错当成 hand trajectory（手轨迹）的前提下，把 E8 的 whole-object projection / whole-object gate 升级成：

> contact-local / part-aware projection + part-aware gate

E9 的主线方案包括 4 个部分。

### 1. contact part mask（接触部件区域）

E8 虽然已经把 contact point（接触点）投影到 reference frame（参考帧）里的 object mask（物体掩码）上，但 gate 仍然是 whole-object 级别。也就是说，只要 projected contact（投影后的接触点）还落在整个物体 mask 里，就可能被放行。

E9 在 contact frame（接触帧）和 reference frame 都构造更局部的 `contact_part_mask`，让 gate 不再只问“是否还在物体上”，而是进一步问：

> 是否仍然落在正确的接触部件上？

构造 `contact_part_mask` 时，综合使用：

- contact GMM means；
- raw contact points；
- hand-object 接触边界附近区域；
- object boundary band（物体边界带）；
- noun-conditioned soft prior（基于名词类别的软规则先验）。

### 2. noun-conditioned part prior（名词条件部件先验）

E9 没有引入复杂 part classifier（部件分类器），而是加了一组轻量软规则：

- `pan / pot / knife / peeler`：优先细长边缘、端部、handle-like（把手状）区域；
- `drawer / door / cupboard / freezer / fridge`：优先边缘、门缝、handle-like 区域；
- `tap`：优先 knob / spout（旋钮 / 出水口）附近；
- `potato / egg` 等小物体：允许 whole-object mask 作为较宽松的 part 表示。

这些规则不是硬裁剪，而是影响局部采样和 part gate 的偏置方向。

### 3. contact-part dominated tracking（接触局部主导的跟踪点采样）

E8 的跟踪点采样会混合 contact-near / boundary / interior（接触附近 / 边界 / 内部）点。这样做的风险是：

- 大面积锅身、门板、箱门中心区域会主导 affine（仿射）估计；
- 真正语义接触区域反而被整物体几何稀释。

E9 把采样改成：

```python
sample_contact_part_points_for_tracking(...)
```

策略是：

- 优先从 `contact_part_mask` 采样；
- 不够时补 local boundary（局部边界）；
- 最后才补 whole-object boundary；
- 尽量不再大量使用 object interior（物体内部）点。

### 4. part-aware local projection + continuation entry rescue

E9 的投影优先使用：

> contact_part_local_affine

即用接触局部采样点跟踪后拟合局部 affine，把 5 个 GMM center 投影到参考帧。

最终 gate 也不再是 whole-object mask gate，而是：

> projected contact 是否落在 reference contact part 上

此外，E9 第二轮修正里还增加了一个非常有限的补救：

> `continuation_entry_rescue`

它只在一个 subaction 内完全没有 `new_contact_episode` 候选时才启用，只取 subaction 入口处仍在持续接触的那一小段候选。这样做的目的不是“把 continuation contact 全收进来”，而是修正 annotation / subaction 切分导致的边界断点问题。

## 二、E9 要解决的问题

E9 主要想解决 3 类问题。

### 1. E8 的 whole-object gate 太粗

E8 已经比 E7 更接近 object-centric（面向物体）的投影，但它仍然默认：

> 只要接触点还落在目标物 mask 内，就算合理。

这会导致典型错误：

- `pan` 的接触语义本应在 handle（把手），但 E8 可能把点放到锅身中央；
- `door / drawer` 的接触语义本应在边缘或把手，E8 可能落到整块门板中心；
- `knife / peeler` 的接触语义本应在柄部或某个端部，但 E8 可能落在刀身中段。

### 2. whole-object tracking 容易被大面积区域主导

对于锅、门、抽屉、柜门这类物体，整物体上的点非常多，而真正接触区域只占很小一部分。E8 的 affine 容易被大面积区域带偏，造成：

- 投影点仍在物体上，但不在正确部件上；
- 对 articulated object（可开合物体）局部运动描述不够准确。

### 3. subaction 边界处的 candidate 缺失

E8 严格只接受当前 subaction 内部发生的 `0 -> 1` new contact episode（新接触开始）。这样虽然语义保守，但也会丢掉一类真实可用样本：

- 接触其实在上一个 subaction 尾部已经开始；
- 当前 subaction 一开始就已经处于稳定接触状态；
- 因为本 subaction 内没有新的 `0 -> 1`，所以直接 `deep_run=0`。

这类情况在 `pick up pan`、`move potato`、`peel potato`、`put down potato` 等片段里都很明显。

## 三、E9 的处理效果

E9 一共跑了两轮。

### 1. 第一轮 E9

第一轮只做了 part-aware local projection 和 part-aware gate，但没有处理 continuation-only subaction 的边界问题。结果是：

- 覆盖 subaction：`57/100`
- final tuple：`119`

这个结果不但没有超过 E8，反而比 E8 还低，说明第一版 E9 的局部约束虽然更强，但候选入口过窄，且 part mask 初版偏保守。

### 2. 第二轮 E9（最终版本）

第二轮做了两个关键修正：

1. `contact_part_mask` 不再把 contact local 区域压得过窄，而是保证接触局部一定保留，noun prior 只做 soft bias（软偏置）；
2. 增加 `continuation_entry_rescue`，只在没有 `new_contact_episode` 候选时启用。

最终结果：

- 成功覆盖 subaction：`74/100`
- final tuple：`147`
- deep run candidate total：`624`
- object track success：`386`
- reference found：`346`
- projection success：`346`
- part gate pass：`346`

新增覆盖的 subaction 一共有 `14` 个，相比 E8 没有丢失任何一个原本已成功的 subaction。

新增覆盖的 subaction 为：

`[4, 5, 7, 15, 41, 57, 59, 60, 70, 72, 78, 94, 98, 99]`

这些新增覆盖基本都来自：

- subaction 边界处的 continuation contact；
- 但又能在 E9 的局部投影 + part gate 下通过质量筛选的样本。

## 四、与之前方案在通过率指标上的对比

这里主要看 subaction 覆盖数和 final tuple 数。

| 实验 | 核心方案 | 覆盖 subaction | final tuple |
| --- | --- | ---: | ---: |
| E7 | object tracking + bbox / local flow gate | 43 | 43 |
| E8 | mask point tracking + whole-object mask gate | 60 | 131 |
| E9 第一轮 | contact-part local projection + strict part gate | 57 | 119 |
| E9 最终版 | contact-part local projection + part gate + continuation entry rescue | 74 | 147 |

可以看到：

1. `E7 -> E8` 的主要提升，是从 bbox / object-aware 粗门控升级到 mask-based projection（基于掩码的投影）。
2. `E8 -> E9` 的主要提升，不是简单调 threshold，而是：
   - 让投影更偏向真实接触局部；
   - 让 gate 从 whole-object 升级到 part-aware；
   - 修复 subaction 边界处 “有接触但无 new-contact 候选” 的结构性漏召。

E9 相比 E8 的增量是：

- subaction 覆盖：`60 -> 74`，增加 `14`
- final tuple：`131 -> 147`，增加 `16`

虽然还没有达到目标中的 `82/100`，但已经明显优于 E8。

## 五、还存在哪些问题未解决

E9 还没有解决的问题，主要集中在 4 类。

### 1. CoTracker 仍未真正启用

本次运行环境中，CoTracker 仍然不可用：

- `cotracker_init_status = failed`
- `cotracker_init_error = ModuleNotFoundError:No module named 'torch'`

因此当前 E9 的所有成功样本，tracker backend 仍然是：

- `fallback_lk`

这意味着 E9 的提升主要来自：

- 更好的局部部件建模；
- 更合理的候选入口；

而不是更强的时序跟踪器本身。

### 2. track confidence 仍是最大失败项

最终 E9 的主要失败原因中，第一位是：

- `track_confidence_below_threshold = 81`

这说明还有相当多 candidate 不是被 part gate 拒掉，而是在更前面的物体跟踪阶段就失败了。也就是说：

> 剩余瓶颈已经不完全是“投影错不对”，而是“能不能先稳定跟踪到参考帧”。

### 3. detection 缺失仍然很多

另一个主要失败原因是：

- `missing_hand_or_object_bbox = 79`

只要 active hand bbox 或 active object bbox 缺失，后续流程基本无法成立。这类问题无法靠 part-aware gate 本身解决。

### 4. contact 点本身不足

仍然有很多样本死在：

- `contact_points_lt5_after_object_boundary_filter = 71`

这说明对部分小物体、细长物体或遮挡严重帧，接触区域本身就不够稳定，连 5 个可用 contact points 都拿不到，更别说后面的 GMM 和局部投影。

## 六、哪些地方效果不够好

### 1. 距离目标 `82/100` 还差 `8`

E9 最终达到 `74/100`，已经显著好于 E8，但还没有达到预期中的接近 `82/100`。

目前没补上的 26 个 subaction 中，主导失败原因是：

- `track_confidence_below_threshold`
- `missing_hand_or_object_bbox`
- `contact_points_lt5_after_object_boundary_filter`

这说明剩余问题并不是单纯把 gate 再放松一点就能解决。

### 2. panel / tap / small object 类别仍然不稳定

尽管 E9 已经加了 noun-conditioned prior，但下面这些类别仍不够稳：

- `tap`：局部接触区域太小，容易在 tracking 前就掉；
- `drawer / cupboard / freezer`：有时边缘语义是对的，但 tracking confidence 先过不了；
- `egg / cup / peeler blade`：接触点本身太少，GMM 前就失败。

### 3. articulated object 的局部区域仍然可能漂

对开门、开抽屉、开柜门这类对象，part-aware 思路比 whole-object gate 更合理，但 reference frame 上的 part mask 仍然只是轻量规则构造，不是真正的显式 part segmentation（部件分割）。因此在：

- 开合角度变化较大；
- 遮挡较重；
- reference frame 距离较远；

时，局部区域仍然可能漂。

### 4. continuation rescue 还只是保守补救，不是完整建模

当前 `continuation_entry_rescue` 的设计是保守的：

- 只在没有 `new_contact_episode` 时启用；
- 只取 subaction 入口处的少量帧；
- 仍然要通过 E9 的局部投影与 part gate。

这能修掉一部分边界漏召，但还不能完整描述跨 subaction 的持续接触结构。

---

## 七、结论

E9 最终说明了一件事：

> 在 VRB 这个任务里，真正关键的不只是“接触点能不能投回物体上”，而是“能不能投回正确的物体部件上”，以及“subaction 边界上那些其实可用的持续接触样本，能不能被合理纳入候选”。

从结果上看，E9 相比 E8 已经实现了明显提升：

- `60/100 -> 74/100`
- `131 -> 147`

但它也暴露出新的上限瓶颈：如果 CoTracker 仍不可用、hand/object detection 仍缺失、接触点本身仍不稳定，那么单靠更精细的 part-aware projection（部件感知投影）已经不足以直接把覆盖率推到 `82/100`。

下一步如果继续做 E9 后续版本，更合理的方向应该是：

1. 让 CoTracker / torch 真正可用；
2. 针对 `track_confidence_below_threshold` 做更强的时序跟踪改进；
3. 针对 `contact_points_lt5_after_object_boundary_filter` 改善接触点提取质量；
4. 在保持语义约束的前提下，继续完善 subaction 边界处的 candidate 结构化补救。
