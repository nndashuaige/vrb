# e20-a 2026-7-8

## 一、E20-A 实验设计思路

E20-A 是在 E20 之后重新跑的 Seeing-the-Unseen 同款 hand inpaint 实验。

E20 已经证明两遍式 pipeline 能跑通，但实际使用的是 CPU/Telea strict-QC baseline，结果是 56 个样本里 55 个因为 QC 未通过而保留原图。用户明确要求：

> 现在就想要 Seeing Unseen 同款结果，实验命名为 e20-a，重新跑。

因此 E20-A 的目标不再是 strict-QC baseline，而是：

1. 保留 E20 的两遍式结构；
2. GPU 阶段真正跑 SAM ViT-H mask、LaMa、Stable Diffusion inpainting、SDEdit/img2img；
3. 所有 LaMa/SD 候选图都保存下来；
4. final 阶段采用 seeded 50/50 风格在 LaMa/SD 中选择一版；
5. 即使严格 QC 未通过，也保留生成结果，但在 manifest 中明确标记 `final_inpainted_qc_failed` 和 `qc_passed_final=false`。

换句话说，E20-A 是"SU 同款候选结果优先"版本，不是"严格复检全通过"版本。

## 二、Seeing-the-Unseen 对应关系

E20-A 对 Seeing-the-Unseen 的迁移如下：

| SU 环节 | E20-A 实现 |
| --- | --- |
| SAM ViT-H 分割 | `sam_vit_h_4b8939.pth`，box prompt 生成手部 mask |
| LaMa inpaint | `big-lama.pt` |
| SD inpainting | `runwayml/stable-diffusion-inpainting` |
| SDEdit / img2img | `runwayml/stable-diffusion-v1-5`，prompt `high resolution, 4k` |
| 复检过滤 | YCrCb 肤色比例、boundary_delta、mask_area_ratio、mask 外像素一致性 |
| 标签保持 | 不在 GPU 阶段画标签；本地 finalize 用缓存几何参数重绘 |

注意：计划中原本写的是 `stabilityai/stable-diffusion-2-inpainting`。实际服务器侧从官方/HF 镜像都无法稳定取得该模型，HF mirror 上该 repo 返回不可用；所以 E20-A 改用可下载的 `runwayml/stable-diffusion-inpainting` 作为 SD inpainting 分支。流程同款，但 SD 模型不是完全同一个。

远端 GPU 运行命令核心参数：

```bash
cd /root/workspace/vrb/e20a_gpu_job
export SAM_CHECKPOINT=/root/workspace/vrb/models/sam_vit_h_4b8939.pth
export LAMA_MODEL=/root/workspace/vrb/models/big-lama.pt
export HF_ENDPOINT=https://hf-mirror.com
export HF_HUB_DISABLE_XET=1
export HF_HOME=/root/workspace/vrb/cache/huggingface
export E20_SD_INPAINT_MODEL=runwayml/stable-diffusion-inpainting
export E20_SDEDIT_MODEL=runwayml/stable-diffusion-v1-5
export E20_DIFFUSERS_VARIANT=fp16

/opt/anaconda/bin/python run_e20_server.py \
  --job-dir . \
  --out-dir /root/workspace/vrb/e20a_gpu_results \
  --device cuda \
  --backends lama,sd \
  --sdedit 1 \
  --limit 56
```

本地 ingest 使用：

```bash
E20_FINAL_POLICY=prefer_generated \
PYTHONPATH=src \
python scripts/run_e20.py --stage ingest \
  --output-root outputs/e20-a \
  --results-tar outputs/e20-a/e20a_gpu_results.tar.gz
```

`E20_FINAL_POLICY=prefer_generated` 是 E20-A 和 E20 的关键区别：当严格 QC 没有任何 backend 通过，但 LaMa/SD 候选图已经生成时，仍按 seeded 选择一版作为 final，并把 QC 失败写入 manifest。

## 九、质量观察

肉眼检查 contact sheet 第 1 页后，结论是：

- pipeline 产物完整，LaMa/SD/SDEdit 均实际跑通；
- 标签重绘正确，`redraw_selfcheck_max_diff=0`；
- 但很多样本仍有明显手/手臂残留，尤其是 mask 覆盖手臂、手压住目标区域、mask 面积较大的样本；
- 严格 QC 大面积失败是合理的，不是统计脚本误判。

因此 E20-A 当前产物适合称为：

> Seeing-the-Unseen 风格 inpaint 候选结果 + 标签重绘结果。

不适合直接称为：

> 56 个全部干净通过的无手训练样本。

## 十、踩坑和修正

1. `mediapipe 0.10.35` 在服务器上没有旧的 `mp.solutions.hands` API，worker 已改成缺 API 时安全返回空 bbox，不让 MediaPipe fallback 中断主流程。
2. diffusers 加载增加了 `E20_SD_INPAINT_MODEL`、`E20_SDEDIT_MODEL`、`E20_DIFFUSERS_VARIANT`、`use_safetensors=True` 和 `enable_attention_slicing()`，用于适配 HF mirror 下载的 fp16 safetensors。
3. SmoothCloud 的 SSH/SCP 有时返回 255/1，但文件和日志实际成功；后续应以 `tmux has-session`、日志、文件计数、tar 校验为准。
4. `results_tar` 顶层目录最初写死为 `e20_gpu_results`，E20-A 的 tar 是 `e20a_gpu_results`，后来已改成自动识别 `*_gpu_results`。
5. SD2 inpainting 原模型不可用时，必须在实验记录里显式写替代模型，避免以后误以为完全同模型复现。

## 十一、结论

1. E20-A 成功跑通了 SU 风格 GPU inpaint 流程：SAM ViT-H、LaMa、SD inpainting、SDEdit、QC、标签重绘全部完成。
2. 56 个样本全部有 final 结果，LaMa/SD 最终选择为 32/24，GPU 主流程耗时 115 秒。
3. 标签重绘链路可靠，56 个样本 `selfcheck=0`。
4. 质量瓶颈已经从"流程能不能跑"转为"mask 和 inpaint 是否真的能去掉手/手臂"。
5. 后续如果要得到可直接训练的 Tier-A 数据，需要改进 mask 策略、手臂扩展、QC 阈值和人工/自动筛选，而不是继续只改 finalize 逻辑。
