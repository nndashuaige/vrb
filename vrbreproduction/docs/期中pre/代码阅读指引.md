# E12 / E16 / E17 代码阅读指引

本文整理三个实验版本的阅读顺序、方法差异和筛选漏斗。建议先看 E16，再看 E17，最后看 E12：E16 最接近论文语义，E17 用来诊断 reference 约束是否过严，E12 是更工程化的 contact-part-aware 改进版本。

## 一句话总览

| 实验  | 方法一句话                                                                                                                       |                           最终结果 |
| --- | --------------------------------------------------------------------------------------------------------------------------- | -----------------------------: |
| E16 | 只取每个 subaction 的第一个新接触帧，reference 要求 active hand invisible，尽量贴近论文中 handless reference 的语义。                                  |            26 / 100 subactions |
| E17 | 仍只取第一个新接触帧，但 reference 改成 contact 前 5-10 帧内最近可用帧，不要求 handless，用来诊断 reference 距离和严格度的影响。                                     |            47 / 100 subactions |
| E12 | 投影方法没按原文，使用的sam+cotracker。多 candidate 深跑，使用 contact part mask、局部仿射/CoTracker 和 part-aware gate，每个 subaction 最多导出 3 个 tuple。 | 79 / 100 subactions，156 tuples |

## 方法区别

### E16: active-hand-invisible reference baseline

E16 的核心目标是验证“论文语义路线”是否能跑通。它先在每个 subaction 内找到 smoothed contact 从 0 到 1 的第一个 contact episode，只取 episode 的 start frame 作为 contact frame。然后向 contact 之前回看，最多回看 360 帧，寻找最近的 active hand invisible reference frame。

这里的 active hand invisible 不是 strict humanless。它不要求画面完全无手，也不要求另一只手不可见，只要求当前发生接触的那只 active hand 在 reference frame 中不可见。找不到这种 reference 的样本直接失败，不用 E14 的 clean pre-contact reference 救回。

直观理解：E16 问的是，如果按“接触前、主动手还没出现”的思路做 reference，当前 pipeline 能保留多少样本。

### E17: near-contact reference diagnostic baseline

E17 保留 E16 的 contact 选择方式：每个 subaction 只取第一个新接触 episode 的 start frame，也就是 first contact timestep。它只改 reference：不再要求 active hand invisible，也不要求 strict humanless 或 E14 clean gate，而是在 contact frame 前 5-10 帧里选最近可用帧。

E17 是诊断实验，不是 paper-faithful baseline。它的目的不是证明最终方法正确，而是回答一个问题：如果 reference 离 contact 很近，并且不再被 handless 条件卡住，homography 和后续 heatmap 是否明显更稳定。

结果显示 E17 的 reference 找到率从 E16 的 38 提高到 81，最终成功从 26 提高到 47，说明 E16 的一个重要瓶颈确实是 reference 选择过严、过远。

### E12: contact-part-aware local projection

E12 走的是另一条工程改进路线。它不再只依赖 whole-object projection，而是在 contact frame 上构造 whole-object mask，再结合 contact GMM、raw contact points、hand bbox 和 noun prior 形成 contact part mask。跟踪点优先从 contact part 采样，只在局部点不足时补 whole-object boundary。

投影时，E12 优先使用 contact-part local affine；局部仿射不稳定时才考虑 fallback。gate 也从 whole-object gate 升级为 part-aware gate：投影后的 contact point 要落在 reference contact part 附近，避免整物体大区域掩盖局部接触失败。

直观理解：E12 不只是“找 reference”，而是把接触区域本身做得更局部、更稳定，所以它能覆盖 79 个 subaction，并导出 156 个最终训练 tuple。

## Subaction 漏斗

E16 和 E17 是 one candidate per subaction 的实验，漏斗可以直接按 subaction 理解。E12 的完整 summary 同时记录 candidate/tuple 口径，因此这里先给 subaction 口径，再补充 candidate/tuple 口径。

### E16 subaction 漏斗

| 阶段                                    | 剩余 subactions | 本级筛掉 | 直观含义                                   |
| ------------------------------------- | ------------: | ---: | -------------------------------------- |
| 原始输入                                  |           100 |    - | P01_109 前 100 条 annotation             |
| 有 new-contact episode                 |            81 |   19 | subaction 内有新接触开始帧                     |
| Cell2 contact / GMM pass              |            59 |   22 | 接触点足够稳定，能拟合 GMM                        |
| active-hand-invisible reference found |            38 |   21 | 接触前能找到 active hand 不可见的 reference      |
| homography available                  |            29 |    9 | reference 到 contact 的逐帧 homography 链可用 |
| geometry pass                         |            26 |    3 | 投影几何合理                                 |
| heatmap pass / final keep             |            26 |    0 | 最终 heatmap 和 tuple 可用                  |

主失败原因：`no_active_hand_invisible_reference`。也就是说，很多样本不是 contact frame 不存在，而是 contact 前一直能看到 active hand，导致 reference 规则过严。

### E17 subaction 漏斗

| 阶段 | 剩余 subactions | 本级筛掉 | 直观含义 |
| --- | ---: | ---: | --- |
| 原始输入 | 100 | - | P01_109 前 100 条 annotation |
| 有 new-contact episode | 81 | 19 | subaction 内有新接触开始帧 |
| near-contact reference found | 81 | 0 | contact 前 5-10 帧能找到 reference |
| Cell2 contact / GMM pass | 59 | 22 | 接触点足够稳定，能拟合 GMM |
| homography available | 52 | 7 | 短距离 reference 让 homography 更容易打通 |
| geometry pass | 47 | 5 | 投影几何合理 |

E17 的关键结论是 reference 基本不再是主瓶颈。只要有 new-contact episode，near-contact reference 几乎都能找到；剩下的主要瓶颈转移到 Cell2 contact/GMM 和几何质量。

## 代码阅读指南

### 先读公共概念

1. `vrbreproduction/outputs/e16/summary.md`
   先读 E16 的定义、Funnel 和失败原因，建立 one-subaction-one-candidate 的基准视角。
2. `vrbreproduction/outputs/e17/summary.md`
   对照 E16，看 reference 从 active-hand-invisible 改成 near-contact 后，漏斗在哪些阶段改善。
3. `vrbreproduction/outputs/e12/summary.md`
   最后读 E12，注意它的 subaction 覆盖和 candidate/tuple 统计口径不同。

### E16 代码阅读顺序

入口文件：

```text
vrbreproduction/src/vrbreproduction/e16_active_hand_invisible_reference.py
```

推荐顺序：

1. `E16Config`
   看默认视频、subaction 数量、reference 回看窗口、输入输出路径。
2. `build_contact_arrays()`, `segment_contact_runs()`, `build_new_contact_runs()`
   看如何从 HOA hand state 得到 smoothed contact episode。
3. `runs_for_subaction()`
   看每个 subaction 如何只保留第一个 new-contact episode。
4. `Problem3CachedRunnerE16`
   看 active-hand-invisible reference 如何选择，以及 homography 缓存如何工作。
5. `run_one_candidate()`
   看一个 candidate 从 Cell2、reference、homography、geometry 到 Cell4 heatmap 的完整路径。
6. `summarize_subactions()`, `build_overview()`
   看漏斗数字如何汇总。
7. `write_markdown_report()`, `run_e16_experiment()`
   看 summary、CSV、图表和 pipeline outputs 如何写出。

### E17 代码阅读顺序

入口文件：

```text
vrbreproduction/src/vrbreproduction/e17_near_contact_reference.py
```

推荐顺序：

1. `E17Config`
   看 reference offsets 默认是 `5,6,7,8,9,10`。
2. `runs_for_subaction()`
   确认 E17 和 E16 一样，只取第一个 new-contact episode。
3. `preselect_near_contact_reference()`
   先看 E17 与 E16 的核心差异：reference 直接从 contact 前 5-10 帧里选。
4. `Problem3CachedRunnerE17`
   看 near-contact reference、strict humanless shadow、active-hand-invisible shadow、E14 clean shadow diagnostics 如何记录。
5. `run_one_candidate()`
   看 E17 的 Cell2、reference、homography、geometry、Cell4 heatmap 如何串起来。
6. `build_overview()`
   看 `near_contact_ref_found`、`active_hand_invisible_ref_found`、`clean_ref_found` 等统计字段。
7. `write_markdown_report()`, `run_e17_experiment()`
   看最终 summary 和图表输出。

E17 还调用：

```text
vrbreproduction/src/vrbreproduction/e14_clean_pre_contact_reference.py
vrbreproduction/src/vrbreproduction/contact_point_utils.py
vrbreproduction/src/vrbreproduction/problem3_utils.py
vrbreproduction/src/vrbreproduction/pipeline_retention.py
vrbreproduction/src/vrbreproduction/label_heatmap_utils.py
```

### E12 代码阅读顺序

入口文件：

```text
vrbreproduction/src/vrbreproduction/e12_target_aware_clean_reference_projection.py
```

推荐顺序：

1. `E12Config`
   看 E12 的输出目录、top-k、tracking、mask、reference 相关配置。
2. `build_candidates_for_subaction()`
   看 E12 为什么会有多 candidate，而不是像 E16/E17 每个 subaction 只取一个。
3. `build_contact_part_mask()`
   看 contact part mask 如何由 contact GMM、hand bbox、object mask 和 noun prior 组成。
4. `get_object_mask()`
   看 object mask 来源，包括 SAM2、VISOR、GrabCut fallback、bbox fallback。
5. `sample_contact_part_points_for_tracking()` 和 `track_object_points_to_reference()`
   看 E12 如何围绕 contact part 采样和跟踪。
6. `estimate_contact_projection_from_tracks()`
   看 contact point 如何通过局部 tracking/affine 投影到 reference。
7. `part_aware_projection_gate()`
   看 E12 的关键 gate：不只看 whole object，而看 projected contact 是否落在 contact part 附近。
8. `evaluate_reference_candidates()`
   看 reference cleanliness、projection score、gap penalty 如何共同决定 reference。
9. `run_one_candidate()`
   看一个 candidate 的完整深跑路径。
10. `finalize_one_sample_per_subaction()`, `summarize_subactions()`, `build_overview()`
    看 top-k tuple、subaction 覆盖和 overview 统计如何生成。
11. `write_summary()`, `run_e12_experiment()`
    看报告、CSV、图表和 manifest 输出。

E12 代码更长，阅读时不要从文件头一直顺序读到底。先按上面的主线读，再回头看 mask、tracking、reference cleanliness 的辅助函数。

## 推荐汇报叙事顺序

1. 先讲 E16：按论文语义做 active-hand-invisible reference，结果只有 26/100，主要卡在 reference 和 homography。
2. 再讲 E17：只改 reference 为 contact 前 5-10 帧，成功提高到 47/100，证明 reference 距离和严格度是重要瓶颈。
3. 最后讲 E12：换成 contact-part-aware local projection，目标不再只是放宽 reference，而是让接触区域的投影、跟踪和 gate 更局部、更稳定，最终覆盖 79/100 subactions。
